# KookieUI v2

Ground-up rebuild of KookieUI. Base UI primitives behind a Kookie-owned API, generated OKLCH color, token-only styling, semantic axes, hard CSS budget.

## State

Blockers resolved 2026-07-31; code phase open, following §14's build order strictly.

No runtime touch reserve: the designed geometry carries both the locked 24 floor (WCAG 2.2 AA) and the 44 target on the default path, so every control is one element. **Button shipped 2026-08-03 (step 5)** on Base UI, the first runtime dependency: `size × tone × emphasis × bordered × loading`, plus Spinner. Exit gate met — +1,206 bytes gzipped for the whole control layer, of which ~480 is Button's own; additivity is law-tested, not just measured. Confirmed on a real iPhone. All transitions are zero until the motion system is designed (Kushagra's call; press stays instant whenever motion lands). **`material` returned 2026-08-04, and became a fill MODIFIER the same day** (§10 "Material is a fill modifier"): the veil is the component's *own* fill mixed toward transparent at the thickness alpha (`--kui-fill-src` indirection in both layers) — tone and loudness survive the glass, quiet is bare blur, the rung keeps its own label pairing, interaction steps the mix alphas, the filter never moves with state. Card is the special case (seal @ alpha = page glass, visually unchanged); derived fills carry `@property inherits:false` guards. v0 alphas, judged in the preview.

**Card shipped 2026-08-03 (step 6), then stripped to a shell 2026-08-04**: `size × material` (solid | thin | regular | thick) and children, one fixed treatment (opaque --color-surface seal + border), no tone/emphasis/bordered props, no anatomy slots, zero CSS of its own (a law asserts card.css does not exist). The governing criterion (LOG 2026-08-04): anatomy is system-owned only where something non-visual forces it (Dialog a11y, Callout status); layouts are blocks (kookie-blocks). Card-as-button is `render={<button/>}` — the surface layer notices element semantics.

**The elevation axis is deleted; depth is an app identity.** No call site chooses a shadow. Theme `surfaces="flat"|"elevated"` (sixth Theme prop) is the one sanctioned consumer: --surface-chrome composes var(--shadow-2), the border stays --tone-border (sharp, and contrast="high" reaches it), dark adds only the inset rim-light. --shadow-1..4 is otherwise a §13 resource for escapes/blocks via `style`.

**Layout space shipped 2026-08-04 (§3, §12):** `--layout-space-N`, the density-aware semantic layer every layout distance consumes — gap on Flex/Stack/Grid, Box `p`/`m`, surface padding (fixed picks, re-baked per density scope). Default is the 1:1 identity map onto the untouched space palette; compact/comfortable shift picks for steps 1-8 while the gutter band 9-12 holds. Raw space = palette + control-family picks (innards answer density via the designed sets, never twice); pointer never touches the layer. Preview has a page-wide density select.

**Surface radius is size-indexed (2026-08-04, §6):** `--radius-surface-1..4` picks from a widened surface band (palette 0-10: control 1-5, surface 6-9, overlay 10); size 3 anchors each level's old flat value; density never touches a surface corner; the semantics re-declare in every `[data-radius]` block (substitution-at-declaration). The preview's demos now space exclusively through kuiBox (flex + gap via the real resolver) — demos modeling margins was called out as a law violation and fixed.

**Audited 2026-08-03 (multi-agent, adversarially verified), and the findings are fixed.** Twenty-two defects, clustered in two places. The escape scopes: `contrast="high"` resolved **no rule at all** in light (the block was `:root`-scoped; Theme renders a div), `prefers-contrast: more` could never fire in dark (Theme stamped the `normal` the guard excludes), and `appearance="light"` had no block, so a light section inside a dark app stayed dark. The claimed-versus-actual law surface: four guarantees the docs named as CI-asserted could not fail, and writing them exposed a WCAG 2.4.11 failure — the dark focus ring sat at |Lc| 22 against the page and is now step 11 per mode. Also fixed: `inset` and `overflow` shipped as dead no-ops (shorthand before longhand, the §2 defect LOG 2026-08-02 already records fixing once for padding); `render={<a/>}` emitted `type="button"` and a focusable unannounced dead link; the `render` escape overwrote the target's ref, style and children; the control size join leaked the whole control family onto every Card; the chrome widths were raw px and the only geometry ignoring `--scale`; dark's seal had no hover step; `surfaces="flat"` could not escape an elevated ancestor; and `build` regenerated the very files the drift laws read, so ENGINEERING's "a hand edit fails CI for everyone" was false.

**The lesson, and the standing rule it earned:** every broken axis was one where no law read a *computed value*. The tests asserted attribute strings, token *names*, and in-memory objects — each one indirection short of the thing that could be wrong, and in each case that thing was wrong. An axis is now proven by a law that reads a computed token through a mounted `<Theme>` in both appearances, or the emitted declarations where the question is what the generator wrote. Every fix in that sweep was falsified against the pre-fix code before it was accepted. 299 tests (was 265); budget 9358 → 9584 gzipped, re-recorded per commit.

**Text + Heading shipped 2026-08-04 (§15)**, the first of the post-slice repetition: one type system through two family slots — `size` 1–9 joining the paired scales, `weight` as token names, no tone (they read the surface's foreground context, §11) — resolved by the shared type layer `system/type.css`; neither ships CSS of its own, law-tested, and type's density/pointer invariance is a mounted law. **`emphasis` reached type the same day** (Kushagra's call), the third resolution of the one axis: fills for controls, dressing for surfaces, foreground roles here — loud `--color-text`, medium muted, quiet the new faint role (v0 neutral-10). Text rests loud (full contrast is the accessible resting state for reading); on a loud surface the ladder collapses to `--tone-contrast`. **`tone` followed the same day** (Kushagra: full ladder per family, semantic only): the ink trio `--{tone}-ink/-ink-muted/-ink-faint` joins the tone indirection — neutral's inks are steps 12/11/10 (≡ the tone-less roles), a chroma family's loud ink is its one designed text colour (11) and the lower rungs fade it via color-mix (v0 percentages). Stamped only when chosen; an explicit tone survives the loud-surface collapse. **The tone set widened to six the same day** (Kushagra: "a few basic families", the middle ground vs Radix's 30): blue/green/orange join as colour-as-data vocabulary, ~1.15KB gzipped each, `Tone` derives from config. The widening caught a generator drift — the state-direction code didn't implement its own comment's rule — fixed as a flip GATED on the APCA label law. **Amber joined 2026-08-05 at vividness 0.9** — the refusal was real, but the input space was not exhausted: at full vividness the resting solid parks ON the sRGB cusp, where the mud-guard halts state travel at .032 against a .035 floor (refused by .003, which is why the preview looked fine while the law said no); ten percent off the cusp buys the visible press state, and no generator exception was ever needed. LOG records the declined brighter routes, including Radix's own carry-the-light-pin-into-dark. **The semantic core completed the same day** (§2, §7, Kushagra closing the standing open question): success/warning/info join for **ten tones**, each its OWN generated family resolving to an already-judged pigment — success on green's hue, warning on amber's (the cusp finding is what made warning possible), info on blue's — never an alias, so a meaning stays independently correctable without dragging the data colour it currently shares a hue with. **Accent became hue-authored the same day**: `{ hue: 250, vividness: 1 }`, blue's own recipe rather than a pinned copy of its rendered hex, so the two resolve identically by construction and cannot drift (−539 bytes: accent ≡ blue compresses).

**TextField shipped 2026-08-04 — repetition's first entry, and the additivity claim's first real test.** `size × material` + `leading`/`trailing` slots + the native input's props, for **+247 bytes gzipped** (against Button's +1,206 for the layer it created). No emphasis and no tone: loudness ranks actions, and a form where one field is louder than the next names nothing. The visible control is a WRAPPER around the input — which is what makes slots legitimate anatomy here after Card refused them (the border cannot stay on the `<input>` once an icon sits inside it, and the wrapper then owes caret-on-click, slot-aware layout, and a trailing control that keeps its own press). Validity is state (`aria-invalid` / Base UI's `data-invalid`), and its tone remap went into the SHARED layer beside disabled. Focus rings when the caret is in it — a field's focus is a mode, not a keyboard affordance. `ref` goes to the input; `className`/`style` dress the wrapper. **The value wears content dress (2026-08-05, §15):** regular weight, not the skeleton's medium — a button-label decision that reached the input through `font: inherit`, inherited and never decided; slots follow, a hosted control re-declares its own medium. The placeholder is the faint role, whose definition names a placeholder as its case; muted stays the slot colour — an adornment informs, a placeholder invites.

**The audit after it found three "exactly one" claims already stale** (one box-shadow, one focus ring, three cursors), each guarded by a law that counted occurrences in a single file. Both laws now walk every shipped stylesheet and assert the value rather than the count — mutation-checked. Open, in the Open-questions list: TextField's absent `render` escape, and iOS zoom-on-focus at size 1. The adornment spelling closed 2026-08-04 — Button renamed to `leading`/`trailing`.

**A control hosted in a control is now a system rule (§4, 2026-08-04).** Judged in the preview: a trailing button read as a second field wedged inside the field, and it was — measured 1px of slack, 100% of the container's height under coarse at size 1, with the field GROWN 2px past its own size token in 16/16 cells. The system had no rule for nesting, so the call site had to pick a size index, and the mapping it was asked to infer was non-uniform and undefined at size 1. One designed `slotInset` per size now drives all four sides and the hosted height is derived from it; the touch hit area matches the CONTAINER's box rather than 44, so a hosted control never becomes a bigger target than the thing containing it. `iconOnly` lands with it — one Button, not a second IconButton component (v1's, which was opt-in by memory and simply forgotten), with the accessible name required by the type.

**Type bands: `handheld` and `narrow` (§17, split 2026-08-05 — supersedes the single conjunction-gated band).** The one band was doing two unrelated jobs: reading steps rose because a held screen is close to the eye, display steps fell because a narrow screen is seven characters wide. Kushagra caught it from Apple's own page — "iOS, iPadOS Dynamic Type sizes" is ONE table, Body 17pt on both — so the reading question does not distinguish phone from tablet, and our width gate excluded every iPad from a rise it should have had (at 768px it separated an iPad mini in portrait from every other iPad). Now `handheld` on `(pointer: coarse)` owns steps 1-4 and `narrow` on `(max-width: 48rem)` owns steps 8-9; each emits ONLY the steps it moves, so the two cannot fight on a phone where both apply. The four cells are law-tested, including the two that were wrong: a tablet in landscape rises and keeps its 56px display, and a squeezed desktop window cuts display without touching reading sizes. **The `device` prop is DROPPED (2026-08-05, Kushagra)** — its only surviving cases were the kiosk and the POS terminal, which we are not designing for; the band rides the pointer axis's own `[data-pointer]` scopes, so pinning `pointer` forces the whole coarse world, type included, and the preview's pointer select judges phone type (LOG records how to bring it back). **There is no tablet band**: sort what Figma-on-iPad changes and it is features (product), navigation (width), targets (pointer) and type (where Apple says tablet ≡ phone). The real gap it surfaced is **window-level size classes for app-shell layout** — tiers are container-keyed on purpose and nothing answers "which interface should this app show"; recorded open. `any-pointer` closed the same day, for geometry too: capability is not use. Preview says drag the window; the browser suite's viewport is pinned wide, because it had been silently sitting inside the narrow band.

**Control padding left the space palette 2026-08-05 (§3, §12)** — the radius bug one family over. The palette is a layout rhythm whose control band grows ~1.44x per step against a height ladder growing ~1.20x, so an index could not hold a fraction: default ran 0.286 -> 0.500, and coarse/comfortable ran out of palette and repeated a step (size 4 padded no wider than size 3). `px` joins `height` as a designed raw number per set; all 24 cells sit in 0.24-0.38 of their box, held by three laws that each fail against the shipped config. Size 4 down 33%. **`pxPill` joined the designed sets 2026-08-05 (§4, §6):** at `radius="full"` the corner swings inward at the text's cap line and the label read crammed, so full's cells carry their own raw padding (~0.40–0.44 of the box, just under the half-height capsule rule), per density and per pointer world — a raw length has no palette step to ride, so the pointer cells must exist. Applied PER SIDE, read off the DOM: a side whose content starts with a `[data-slot]` wrapper keeps the plain padding, because the slot already stands between the text and the curve. Button's slots got the wrapper they had been missing, which also extended §4's hosted-control geometry to Button. Same day, four TextField audit defects: the ring narrowed from `:focus-within` to the input holding focus (a hosted control was lighting two rings and the field was claiming a focus it did not have); a glass field's fill was still moving because material's mix ramp, not its sources, was what moved; `Field.Root disabled` never reached the wrapper (the shared layer now reads it with the same `:has()` arm `invalid` has); and `children` was typed on the props and spread onto the `<input>`. Plus the invalid remap's DIRECT arm, which had no law at all.

**The remaining audit debts closed 2026-08-05.** The `--kui-h` stem collision: the control layer shared three private names with the layout mechanism (`h`, `px`, `py` against Box's `height`/`px`/`py`), and because layout registers its stems `inherits: false` by NAME, `--kui-h` was silently absent wherever it was not declared — which is why the hosted-control height needed two hops. The control layer now wears `--kui-ct-` (matching surfaces' `--kui-sf-`), the second hop is deleted, and a law forbids any layer from so much as *mentioning* a name layout declares (`--kui-border-color` stays shared on purpose; two laws learned to strip comments so they stop firing on their own documentation). iOS zoom-on-focus: the hole was bigger than size 1 — an iPad in landscape reads as `desktop`, takes the 14px size-2 ladder, and Safari still zooms — so `--input-font-floor` rides the POINTER axis (0 fine / 16 coarse) and floors the input's font alone, leaving the box and label at their designed steps. `readOnly` shipped resolving to nothing and now drops the seal and only the seal (it is not disabled: the value is live, selectable, submitted). `type` closed to a union — unconstrained, `type="hidden"` rendered a visible empty box. Slot content reaches AT through `aria-describedby`, appended to the caller's. And the absent `render` escape is now a recorded refusal with a type law: there are two elements here and neither can move.

**Window size classes shipped 2026-08-05 (§18).** The one viewport question — "which interface should this app show" (container tiers answer a different question: how much room a component has). Three classes, `narrow | regular | wide`, named for room and never hardware (Kushagra's own argument: users run apps in windowed mode, so device names lie; `phone|tablet|desktop` and `narrow|medium|wide|full` both rejected — LOG). Three not four: a class picks the navigation shape and there are three shapes; Material's fourth/fifth compensate for lacking container queries; the set widens by config when a real shell forces it (`expanded` waits, the tone-set rule). The narrow boundary IS the narrow type band's 48rem BY DERIVATION — `narrowMedia` builds from `windowClass.narrowMax`, law-pinned, closing §17's threshold question; boundaries land downward, law-tested at exactly 768/1200. Wide is 75rem (64 opened, moved same day: at 1024 the content behind a sidebar is narrower than a narrow window; 80rem rejected — it puts the boundary exactly on 1280, where half of every 27" display lives; re-judged by eye when a shell exists). Mechanism: `useWindowClass()` over matchMedia — a hook because a shell is components; NO token moves with the class (law: generated CSS never mentions one). SSR returns `null` honestly — and stays null through first paint BY DESIGN: the "one script, both answers" bundling with dark SSR was retracted the same day (LOG) — CSS never needed a window stamp (media queries are native and pre-paint) and the hook cannot read one (hydration must match the server's null branch; next-themes has the same shape). A first-paint shell is CSS-shaped via the exported boundary queries; the hook is for post-mount decisions. Dark mode keeps its inline script alone. `data-window` exists the day pinning does, or never.

**TextArea shipped 2026-08-05 — repetition's second entry, +91 bytes gzipped** (1,206 → 247 → 91: the additivity curve's third point). ONE element, no wrapper, no slots — the anatomy criterion answered twice: TextField's wrapper exists because a slot forces the border off the input; a textarea has no slots, so the border stays on the `<textarea>` and every wrapper debt never exists. The first non-fixed-height control: per §4, padding is the dimension — and the dimension is ONE inset, all four sides (REVERSED same day, LOG "the frame is the inset": the first cut derived block padding from the height so one row matched a TextField, and the residue read as an accident with a second line — centering leftover is not an inset; every real textarea is a paragraph, a composer is its own component). A rows={1} textarea sits taller than a field, accepted; control height survives as min-height; growth is `rows`. `resize` is vertical-only in the stylesheet, NOT a prop (renames raw CSS; `style` is the escape). Shared layer gained the disabled remap's third arm (`.kui-control:disabled` — the control IS the native form element, no stamp). Refused by the type: `children`, `cols`, `render`, `emphasis`/`tone`. Its facts repeat text-field.css self-keyed on purpose; the third field-shaped control promotes the family into the shared layer, not the second (LOG). **It immediately forced a §6 fix (same day, Kushagra caught it in the preview): full's control band now STATES the capsule** — `--radius-control-N: calc(var(--control-height-N)/2)` per (density × pointer) cell — instead of 9999px riding CSS clamping, which asks the RENDERED box and turned a three-row textarea into a stadium. Fixed-height controls render byte-identically; a grown box keeps the one-row curvature; the surface band's per-band precedent applied to the control band; the old law pinning the literal 9999px was the bug's spelling and is rewritten to radius ≡ h/2 (LOG).

**The material grew its own edge and rim 2026-08-05 (§10).** Kushagra, on the preview's glass cards: blur plus the ordinary card border read cheap, and it was — the pane owned only its body (the alpha mix and the filter) and borrowed everything else from systems designed for opaque, in-flow surfaces. The **edge** is the material's own translucent hairline, consumed with a `var(--tone-border)` fallback that resolves at the element — closing §10's long-open "does the material border stay opaque" with the platform answer it had already sketched. The **rim** is a top inner light catch painted as a `background-image` gradient, deliberately not a shadow: `none` is illegal inside a shadow list and flat worlds declare `none`, so a shadow rim would have meant rewriting every one-box-shadow law. And **depth stays the app's** — separation was welded to the glass for an hour and reversed on sight: rim and edge are what the material IS, lift is what the app SAYS, so glass in a flat world gets edge and glint and no shadow. `contrast="high"` leans on the glass rather than unmaking it — a designed `alphaHigh` triple per thickness (more opaque, never fully), with edge and rim emptied so the border falls back to the tone system, the one place that setting can reach an edge. Fading blur was built, judged and reverted the same session (recorded in LOG: cheap and real if scroll-edge chrome ever wants it). +136 bytes; baseline now 17,706 gzipped.

## Non-negotiables

- Components never own outer spacing. No margin prop on any control. The escape is `<Box m>`.
- Tokens only. No raw px in component CSS; every value resolves through a `--*` token.
- No utility classes shipped, ever.
- `size` is an index, not a measurement. Closed unions: `"1" | "2" | "3" | "4"`.
- Appearance is resolved output. Components expose tone/emphasis/material, never raw fills. Elevation does not exist; no component exposes a shadow API. --shadow-1..4 is a fenced resource reached only through --kui-surface-chrome, which Theme surfaces=elevated declares — a law walks every stylesheet and asserts no rule names --shadow-N directly.
- Semantic references, not numeric coincidence (`--radius-control-2`, never `--radius-2` in a component).
- State styling lives in CSS via data-attributes. No JS at interaction time.
- Never edit generated files (they carry a header naming their source config).
- CSS budget is a CI gate, not a goal. Regression fails the build.

## Working rules

- Every implementation task cites the DECISIONS.md section it implements.
- Doc–code drift is a bug. If code forces a decision change, the doc amendment ships in the same commit.
- Follow the build order in DECISIONS.md §14 exactly. Each step has a measurement gate; do not run ahead of a gate.
- Tests assert system laws (token identity, +1-step rule, APCA, budget), never snapshots.
- Commits: conventional style (`docs:`, `feat:`, `fix:`, `chore:`), granular, one concern each.

## Commands

From repo root (pnpm 10 / Node 22; turbo fans out to packages):

- `pnpm run ci` — build + test + lint + budget gate, the full check; run before claiming any task done
- `pnpm run build` — tsdown (JS + d.ts) then Lightning CSS bundle to `dist/styles.css`, then `pack:check` — publint + are-the-types-wrong against the PACKED artifact, so the exports map is verified rather than trusted. attw runs the `esm-only` profile: node10 resolution and `require()` are formally unsupported, not silently untested (LOG 2026-08-05).
- `pnpm run test` — Vitest, two projects: node (generator/config laws) and browser mode (computed values through a mounted `<Theme>`, the standing rule after the audit)
- `pnpm run lint` — ESLint + `tsc --noEmit`
- `pnpm run measure` — CSS budget gate (regression ratchet); numbers live in `packages/ui/budget.json` only. Intentional growth means re-recording `baselineGzipBytes` in the same commit.
- `pnpm --filter @kookie-ui/react run tokens` — regenerate `src/tokens/tokens.css` from `config.ts` (also runs as part of build)
- `pnpm --filter @kookie-ui/react run preview` — emit `packages/ui/preview/density.html`, the size × density matrix for judging the numbers by eye
