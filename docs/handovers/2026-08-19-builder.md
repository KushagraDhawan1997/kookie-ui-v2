# Handover — the builder ships, 2026-08-19

Written for the person who was not in the room. Plain English. Where this file and a
governance doc disagree, the governance doc is right.

The job was Kushagra's ask from this session: a visual GUI builder — drag and drop
components, adjust spacing, export React code — where every distance is a Kookie token and
stating a custom value is deliberately hard. Blocks (a saved "media card", a specific card)
are the point; Storybook-ness is a side effect. Agreed before building: live canvas in a
real `<Theme>`, blocks as frozen subtrees, one Theme identity per document, local-first.

---

## 1. What you can do right now

Open **`/builder`** in the docs app (it's in the site nav). You get three panes:

- **Left — Add / Layers.** The palette is every component the package exports, grouped by
  family, with saved blocks at the bottom. Click inserts next to your selection; drag onto
  the canvas drops into the nearest container whose grammar accepts it. When your selection
  can hold parts (a MenuContent, a Tabs), a contextual "Inside …" group appears at the top.
  Layers is the tree — it's also how you select the state-only roots (Menu, Dialog) that
  render no element of their own.
- **Center — the canvas.** A live render of the real components inside a real `<Theme>`.
  It is not a picture: the menu you inserted opens, the switch flips, the dialog dims the
  page. Click anything to select it (the accent ring).
- **Right — Selected / Theme.** The inspector generates itself from the closed unions: axis
  props are pickers over the real value lists, booleans are switches, content is text. Under
  the controls, **"Not here, on purpose"** shows the component reference's own refusals —
  the missing knobs with the system's argument for why they're missing. The Theme tab is the
  document's one identity (density, radius, pointer, look, depth, material); appearance and
  contrast stay the site's, exactly like /preview.

**Export code** gives you the JSX a person would have written — real imports, only the
props you actually stated, a `<Theme>` wrapper only if your document differs from the
system's defaults, and only the axes that differ. Copy, paste, done. **Save as block**
names the selected subtree and it becomes a palette entry; blocks and the document survive
reload (localStorage; memory is truth, storage is best-effort — the docs' own storage
lesson).

Undo/redo is ⌘Z / ⇧⌘Z (every model operation is pure, so history is a stack of documents).
Reset asks first, with a real AlertDialog.

## 2. Why this builder can't drift, by construction

Every builder ever built fights CSS's infinity and loses — constraints bolted onto an open
substrate leak. This system already deleted the infinity, so the builder only had to NOT
add freedom back:

- There is no coordinate anywhere. "Drag and drop" is tree surgery; position comes from
  Stack/Flex/Grid and token gaps, so the outer-spacing non-negotiable holds inside the tool.
- There is no free length or colour field anywhere. Spacing is an index into the
  layout-space scale; the only free text is content (labels, placeholders).
- The serializer **throws** on any component or prop outside the catalog. Failure mode is
  "no export", never "export with a style attribute".

One data table (`app/builder/catalog.ts`) drives the palette, the inspector, the
containment rules and the insert presets — and its value lists derive from
**`componentAxes`**, the package export this work forced. That was the API decision LOG
2026-08-16 recorded as open ("exporting the axis value lists… waits"); the builder is the
real need that closed it. Nothing in the builder authors a value.

## 3. The laws, and what falsifying them caught

79→81 laws in `app/builder/builder.test.tsx`, all green, the key ones failed on purpose
against sabotaged code first:

- **Coverage:** every package export is placeable or excluded with a written reason ≥40
  chars. One exclusion exists: ScrollArea, because its one job needs a stated raw height —
  the exact value class the builder refuses. Deleting an entry fails CI by name.
- **Round-trip identity:** the exported code is compiled (esbuild) and rendered with
  react-dom/server against the interpreter's clean mode — byte-identical, after normalizing
  React's positional useId salts order-preservingly (aria wiring must still correspond).
- **The sabotage pass earned a law.** `effectiveProps` is one home shared by serializer and
  interpreter — dropping a prop THERE moved both sides identically and round-trip stayed
  green. Agreement is not fidelity: a third law now pins the export to the document's own
  statements ("gap=\"3\"" must appear, etc.).
- Grammar closure (every containment reference names a real entry; every preset satisfies
  the grammar it will be edited under; every part is reachable), serializer refusals,
  sanitize-on-load, and tree-op invariants (clone freshness, no move-into-own-subtree).

Found by actually running `pnpm dev` (the command this repo's history says nobody runs):
the starter document minted ids from a module counter during render; React Strict Mode
double-invokes the state initializer, so server and client hydrated two different
documents. Render-time trees now take stable depth-first ids (`withStableIds`); the global
counter serves only post-mount gestures. The shell law also correctly demanded `/builder`
be listed as a deliberate bare-viewport route — an editor under the site chrome would nest
a scroll inside a scroll.

## 4. Open, on purpose (recorded in LOG's rejected list)

- **JSX import** — refused whole. The document format is truth; code is a build artifact.
- **Axis-level props on blocks** — blocks are frozen subtrees with editable content only;
  parameterizing axes reopens the freedom the system closed.
- **A marked `style` escape panel** — every escape in the tool is an escape in every
  exported block forever. Waits for a real need.
- **v1 scope honesty:** drops append into a container (no between-siblings drop indicator
  yet — reorder is Up/Down in the inspector); TextField/Button `leading`/`trailing` slots
  aren't modeled; Radio label wiring (`htmlFor`) isn't emitted; ScrollArea excluded as
  above. Each is a follow-up, none is load-bearing for the concept.
