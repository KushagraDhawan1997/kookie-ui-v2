Most design systems ship a flat list of components. This system sorts them into families. A
family decides which props its members take.

You can tell a `Card` what material it is made of. You cannot tell a `Checkbox`, because a
checkbox has no material. You can rank a `Button` against the button beside it. You cannot
rank a `MenuItem`, because every item in a menu is equal.

When a component does not have the prop you expect, find its family below. The family is
usually the answer.

## The page, the ground and the card

Three levels sit under any screen. Most people confuse the last two.

The **page** is the lowest level. The library paints no page background, because a `Theme`
that painted one would repaint the page at every nested appearance scope. Use
`--color-page` to paint it yourself.

A **ground** is a region that holds other things. `Surface` is a ground. It has no fill of its
own beyond a small step, and it casts no shadow, because it sits in the page rather than above
it.

A **surface** is an object with its own plane. `Card` is the example. It is opaque, so content
behind it stops at its edge. In an elevated theme it casts a shadow.

```tsx
<Surface size="3">
  <Stack gap="3">
    <Card size="2">
      <Stack gap="2">
        <Heading size="6">api-gateway</Heading>
        <Text size="2" emphasis="medium">Deployed 4 minutes ago</Text>
      </Stack>
    </Card>
    <Card size="2">
      <Stack gap="2">
        <Heading size="6">worker-queue</Heading>
        <Text size="2" emphasis="medium">Deployed 2 hours ago</Text>
      </Stack>
    </Card>
  </Stack>
</Surface>
```

The `Surface` is the bed. The two cards are the objects on it, and each one lifts. Do not nest a
`Card` in a `Card` to get this result.

A `Card` is an object. A `Surface` is what objects sit on. Neither one is a quieter version of
the other. If you are nesting a card in a card to get a quiet region, use a `Surface`.

A card is the one surface that can become a control. Render it as a button and it presses.
Render it as the label of a radio and it can be chosen. It takes no prop for either, because
the element already says which one it is.

## Controls

A control is a thing the user operates. Every control shares one state machine, one size
ladder and one loudness axis. There are four families.

**Buttons** run an action. They rank. `emphasis` sets how loud this action is against the
actions beside it. `tone` sets what the action means. Use one loud control on each screen.

**Fields** hold a value the user types. They do not rank, so `TextField` and `TextArea` take
no `emphasis` and no `tone`. A form where one field is louder than the next says nothing. A
field is also a recess in the plane, not a plane above it, so no field casts a shadow.

**Marks** are controls that are their own mark: `Checkbox`, `Radio`, the `Switch` track and
the `Slider` thumb. A mark leaves the height ladder but keeps the size index, because a mark
sits beside a label instead of containing one. Its ladder is the line box, so a mark is exactly
as tall as one line of the text next to it.

**Instruments** show or set a value along a length: `Slider` and `Progress`. An instrument has
no resting surface and no border, so it takes no material and no dress.

## A mark sits beside its label

The mark and the label are two things in a row. The row sets the distance between them.

```tsx
<Flex align="center" gap="2">
  <Checkbox id="terms" />
  <Text render={<label htmlFor="terms" />}>Email me about releases</Text>
</Flex>
```

No mark takes a `label` prop. A label is text, and `Text` already resolves every size, weight
and ink role that text needs. A `label` prop would add a second, smaller type system inside a
checkbox.

## Rows

A row is one interactive line in a list. A menu item is a row. A navigation item is a row.

A row looks like a small button and is a different kind, for one reason: **rows are equal**.
No option in a list is louder than the options beside it, so the row family takes no
`emphasis` and sets its own quiet value.

The current row is not a louder row. It uses a different colour, so the current row can still
change under the pointer.

A row also leaves the height ladder. A row's height is its text line plus a fixed inset, not a
control height.

## Type, layout and the frame

**Type** components read the ink colour that their surface sets. `Text`, `Heading`,
`Blockquote`, `Code` and `Kbd` have no fill of their own. On type, `emphasis` selects an ink
role instead of a fill.

`Link` is the one type component that answers a pointer, and it is still type rather than a
control. A control is a box: it has a height, a padding, a corner and a target. A link is a run
of words inside a sentence. It has to stay selectable, it has to wrap across lines, and it sits
on the line box the paragraph set. So it takes the states and none of the box.

**Layout** components paint nothing. `Box` is the engine. `Flex`, `Stack` and `Grid` are `Box`
with a fixed `display` and a narrower prop list. They resolve tokens and tiers.

**The frame** is `Shell`. `Shell` is a pattern, not a component. A pattern arranges things it
does not own. A component contains things it owns. If a child has to reach up and configure
its parent, you have built a pattern as a component.

## Two components that look the same

Five pairs render almost the same and belong to different families. Do not compare how they
look. Ask whether you can have one without the other.

- **Tabs or a segmented control.** A tab bar changes what is below it. A segmented control sets
  a value in place. You can change a view without setting a value. You can set a value without
  changing a view. They are two operations, so the segmented control is a radio group and the
  tab bar is not.
- **Dialog or alert dialog.** A dialog holds work you asked for. An alert stops you and asks
  one question. The alert has fixed content, and the system lays that content out.
- **Menu or select.** A menu picks an action. A select picks a value and submits it with a
  form.
- **Link or Button.** A link goes somewhere. A button does something. Ask what happens on
  press: a new address, or a change to the thing you are looking at. A row of accent words that
  submits a form is a `Button` at `emphasis="quiet"`, and a `Link` that runs a handler removes
  the one promise a link makes.
- **Card or Surface.** An object, or the ground it sits on.

When two things look the same, ask what each one does when the other is absent. If the answers
differ, the things differ. One component with two variants would then teach every reader that
the difference is cosmetic.
