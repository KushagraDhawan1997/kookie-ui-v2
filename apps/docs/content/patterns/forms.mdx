A form is a set of labelled values and one action that saves them. The system makes three
decisions for you. Fields don't rank against each other. Checkboxes don't carry their own
labels. Validity isn't a prop. You make all the other decisions: the words, the order and the
grouping.

## The label is a separate element

A label is prose. `Text` already gives prose every size, weight and colour that it needs. For
this reason, no control takes a `label` prop. A `label` prop would put a second, smaller text
system inside a checkbox.

The label is a sibling of the control, so something must connect the two. `Field` connects
them. It supplies the name, the description and the error message. It also connects all three
to the control. You write the words, and `Field` does the wiring.

```tsx
<Field>
  <FieldLabel>Work email</FieldLabel>
  <TextField type="email" />
  <FieldDescription>We use this for receipts.</FieldDescription>
</Field>
```

The order is fixed: label, control, description and error. The label is directly on the
control that it names. All the other text about that control is below it.

Outside a `Field`, you must write the connection yourself. Point `htmlFor` at an `id`, or put
the control inside a `<label>`. Do not use position alone to connect a label to a control.

**A placeholder is not a label.** It disappears when a person starts to type, and its colour is
grey. Use a placeholder for a real example of the value. Do not use it for the name of the
field.

A checkbox or a radio sits next to its label. It does not contain the label. The row that
holds the two sets the distance between them. `FieldItem` is that row. Use one `FieldItem` for
each option.

```tsx
<Field>
  <FieldLabel>Delivery speed</FieldLabel>
  <RadioGroup defaultValue="standard">
    <Stack gap="4">
      <FieldItem>
        <Radio value="standard" />
        <FieldLabel>Standard</FieldLabel>
        <FieldDescription>Three to five business days.</FieldDescription>
      </FieldItem>
      <FieldItem>
        <Radio value="express" />
        <FieldLabel>Express</FieldLabel>
        <FieldDescription>Next business day before noon.</FieldDescription>
      </FieldItem>
    </Stack>
  </RadioGroup>
</Field>
```

A label inside an item names the control next to it. A description inside an item explains
that one option.

## Fields don't rank

`TextField` and `TextArea` take no `emphasis` or `tone`. This is intentional. Loudness ranks
one action against another action. Every field has the same job: a person fills it in.

Show importance with the label, with the order of the form, and with what you leave out. To
mark a field as required, set `required` on the control. If the form is long, also say it in
the label. Only the buttons at the end rank against each other.

## One button saves the form

Use one loud button on each screen. Give it to the action that the form is for. Make all the
other buttons medium or quiet.

```tsx
<Card size="3">
  <Stack gap="6">
    <Stack gap="2">
      <Heading size="6">New project</Heading>
      <Text size="3" emphasis="medium">Anyone in the workspace can open it.</Text>
    </Stack>

    <Stack gap="5">
      <Field>
        <FieldLabel>Project name</FieldLabel>
        <TextField required />
      </Field>
      <Field>
        <FieldItem>
          <Checkbox />
          <FieldLabel>Keep it private for now</FieldLabel>
        </FieldItem>
      </Field>
    </Stack>

    <Flex justify="flex-end" gap="3">
      <Button>Cancel</Button>
      <Button emphasis="loud">Create project</Button>
    </Flex>
  </Stack>
</Card>
```

In that example, three gaps show the structure:

- gap 3 from a label to its field
- gap 5 between the rows of the form
- gap 6 between the title, the form and the buttons

Put the buttons at the end, and align them to the end edge. If there is only one button, you
can make it full width.

Write what the button does. Write "Create project", not "Submit". Then use the same word
through the remaining steps of the flow.

## Group with space

Put related rows closer together than unrelated rows. The standard gaps are gap 3 from a label
to its field, gap 5 between groups and gap 6 between sections.

Keep the gap inside a group at least two steps smaller than the gap around it. If every gap in
a form is the same number, the form looks like one column with no groups.

Do not add a `Separator` or a `Card` where the spacing already makes the group. A container
makes a group, and distance also makes a group. If you use both, you say the same thing two
times. Add a line only where distance cannot do the job. A long settings list is the real
case. Its groups already use the section gap, and something must still divide them.

## Validity is a state, not a prop

There is no `invalid` prop, because nothing chooses to look invalid. The system reads
`aria-invalid`. It also reads the `data-invalid` attribute from Base UI. A control inside a
`Field` gets that attribute automatically.

```tsx
<TextField
  id="email"
  type="email"
  aria-invalid={emailError ? true : undefined}
/>
```

A ticked checkbox is a resting appearance. Invalid is a state, and a state has priority over a
resting appearance. So if a ticked checkbox is also invalid, it looks invalid. Disabled has
priority over both.

The border and the focus ring are the part of the error message that the system supplies. You
supply the words. Colour alone is not sufficient (WCAG 1.4.1). A red field must have words next
to it.

## Use TextArea for a paragraph

Use `TextArea` when the value is prose that a person will read again. Examples are a
description, a note and an address. Its padding above and below is the same as its padding at
the sides. `rows` sets how many lines tall it is at the start. At the default `full` radius,
the sides get a little more padding. A round corner cuts into text that runs from side to side.
It does not cut into text above and below.

There is no `cols` prop. The layout that contains the row sets the width. The `cols` attribute
counts characters. It is older than CSS, and it does not work well with CSS.

A message composer is not a large `TextArea`. A box that needs a toolbar, attachments, a send
button and a rule for growth is a different component. If you make it from a `TextArea`, you
must attach parts to a field that was not made for them.

## Helper text has to change a decision

Write helper text that gives information the label cannot give. Examples are a consequence, a
limit, a scope, or the reason that a control is disabled. Delete any line that repeats what a
person can already see.

```tsx
// Filler. The label above already said this.
<Text size="2" emphasis="medium">Enter your work email address.</Text>

// Useful. A scope the label cannot carry.
<Text size="2" emphasis="medium">Receipts and billing notices go here.</Text>
```

Set helper text at size 2 in the muted colour. This is the same size as the label. If a helper
line is two steps smaller than the text around it, it looks like a mistake.

Do not use size 1 for helper text. The muted and faint colours already say "this is less
important", at a size that people can read.
