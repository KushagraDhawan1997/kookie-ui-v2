Correct components make a screen consistent, but they don't make it good. Every distance
answers to a setting, every colour to a tone, and every size to a step, and you can still put
nine components on one screen at nine different sizes.

These are the rules for putting things together, rather than for using any one component. The
[builder](/builder) checks most of them for you as you work.

## One obvious action per screen

Use one loud control per screen. Give it `tone="accent"` and `emphasis="loud"`, and set every
other control to medium or quiet.

Two loud controls cancel each other out, and nobody can tell which one is the point. This is a
judgment, and it follows the figure-and-ground principle: something can only stand out if
everything around it is quiet.

```tsx
// Wrong. Two loud controls compete.
<Flex gap="3">
  <Button tone="accent" emphasis="loud">Save</Button>
  <Button tone="accent" emphasis="loud">Publish</Button>
</Flex>

// Right. You can still find the second one.
<Flex gap="3">
  <Button emphasis="medium">Save draft</Button>
  <Button tone="accent" emphasis="loud">Publish</Button>
</Flex>
```

Nothing defaults to loud and accent, so a second one is always something you typed on purpose.

The unit is the screen, not the nearest box. A dialog counts as its own screen, because it
covers the page and its loud button is not competing with anything underneath. Two tab panels
never compete either, because you only ever see one at a time.

## Let space do the grouping

Put related things closer together than unrelated things. People group by distance before
they read anything, and more reliably than they group by a border, a fill, or a line. Set the
spacing first. You usually won't need the other three.

Make the gap inside a group at least two steps smaller than the gap around it. The same gap
repeated down a screen shows no structure at all.

```tsx
<Stack gap="6">
  <Stack gap="2">
    <Heading size="6">Notifications</Heading>
    <Text emphasis="medium">Choose what reaches you, and how.</Text>
  </Stack>
  <Stack gap="2">
    <Heading size="6">Billing</Heading>
    <Text emphasis="medium">Cards, invoices and the plan you are on.</Text>
  </Stack>
</Stack>
```

Two levels of separation can sit one step apart. A section at gap 6 holding groups at gap 5
is fine, because both gaps separate groups. The two-step rule is about the inside of a group
against the space around it.

## Five type sizes and one floor

Type is the one thing with no setting to answer to. `size` is a free number, so a written rule
is the only limit on it. Use five steps:

- **Size 8** for the page title.
- **Size 7** for a section title.
- **Size 6** for a card or dialog title.
- **Size 3** for body text.
- **Size 2** for labels and small print.

Don't use size 1 on a real screen. Twelve pixels is for genuinely marginal text. When
something matters less, say so with the muted or faint colour at size 2 or 3.

Move at least two steps to show a rank. A size 4 title above size 3 body text looks like an
accident rather than a hierarchy.

## Use a tone because of what it means

A tone carries a meaning. Don't pick one because the screen looks grey.

```tsx
// Wrong. Green because green is pleasant.
<Text tone="green">Storage used</Text>

// Right. A status word in the family that means it.
<Text tone="success">Backup completed</Text>
```

`success`, `warning`, `info`, and `destructive` mean things. `blue`, `green`, `orange`, and
`amber` are colour used as data: a chart series, a project label, a category.

Use three tones at most on one surface. Four or more look like a palette rather than a set of
meanings. Three look like a legend.

And colour is never the whole message. Write the words too.

## Same job, same size

Every control doing the same job on one surface should be the same size. A row holding a
size 3 button next to a size 2 button looks like two different kinds of control, and you're
left working out why.

Match controls to the surface they're on, as well. A size 3 dialog holds size 3 fields and
size 3 buttons. A control two steps smaller than its container looks like a mistake.

## Write the real words

Put real content into a layout. If the real content does not exist yet, write something of the
same shape and length.

Placeholder text hides the problems: a heading that wraps onto three lines on a phone, a name
longer than its column, a button label that changes the rhythm of a row.

The same goes for helper text. Keep a line that changes what somebody does next. Delete a
line that only restates the label.

## Run the reviewer

Run the reviewer over a real screen before you ship it. Every rule on this page is a live check
in the builder, each finding quotes the sentence it comes from, and each one offers a fix.

Every template that ships with the builder passes every one of these rules, so a rule nobody
could satisfy would break the templates the day it was added.

The reviewer won't tell you whether a screen is good. It tells you whether a screen breaks a
rule this system has already settled.
