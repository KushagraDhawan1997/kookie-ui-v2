Correct components make a screen consistent, but they do not make it good. Every distance comes
from a setting, every colour from a tone and every size from a step. You can still put nine
components on one screen at nine different sizes.

These rules are for putting components together, not for using one component. The
[builder](/builder) checks most of them for you while you work.

## One obvious action per screen

Use one loud control on each screen. Give it `tone="accent"` and `emphasis="loud"`. Set every
other control to medium or quiet.

Two loud controls cancel each other. Nobody can tell which one is the main action. This is a
judgment, and it follows the figure-and-ground principle. Something can stand out only if
everything around it is quiet.

```tsx
// Wrong. Two loud controls compete.
<Flex gap="3">
  <Button tone="accent" emphasis="loud">Save</Button>
  <Button tone="accent" emphasis="loud">Publish</Button>
</Flex>

// Right. You can still find the second one.
<Flex gap="3">
  <Button emphasis="medium">Save draft</Button>
  <Button tone="accent" emphasis="loud">Publish</Button>
</Flex>
```

No component is loud and accent by default. So a second loud control is always something that
you typed on purpose.

Count loud controls on the whole screen, not in the nearest box. A dialog counts as a separate
screen. It covers the page, so its loud button does not compete with anything below it. Two tab
panels also never compete, because you only see one at a time.

## Let space do the grouping

Put related things closer together than unrelated things. People group items by distance
before they read anything. Distance groups items more reliably than a border, a fill or a line.
Set the spacing first. Usually, you will not need the other three.

Make the gap inside a group at least two steps smaller than the gap around it. If a screen
repeats the same gap from top to bottom, it shows no structure.

```tsx
<Stack gap="6">
  <Stack gap="2">
    <Heading size="6">Notifications</Heading>
    <Text emphasis="medium">Choose what reaches you, and how.</Text>
  </Stack>
  <Stack gap="2">
    <Heading size="6">Billing</Heading>
    <Text emphasis="medium">Cards, invoices and the plan you are on.</Text>
  </Stack>
</Stack>
```

Two levels of separation can be one step apart. A section at gap 6 can hold groups at gap 5,
because both gaps separate groups. The two-step rule compares the inside of a group with the
space around it.

## Five type sizes and one floor

Type is the one thing that no setting controls. `size` is a free number, so only a written rule
limits it. Use these five steps:

- **Size 8** for the page title.
- **Size 7** for a section title.
- **Size 6** for a card or dialog title.
- **Size 3** for body text.
- **Size 2** for labels and small print.

Do not use size 1 on a real screen. Twelve pixels is only for text of very low importance.
If something is less important, use the muted or faint colour at size 2 or 3.

To show a rank, move at least two steps. A size 4 title above size 3 body text looks like an
accident, not a hierarchy.

## Use a tone because of what it means

A tone carries a meaning. Do not select a tone because the screen looks grey.

```tsx
// Wrong. Green because green is pleasant.
<Text tone="green">Storage used</Text>

// Right. A status word in the family that means it.
<Text tone="success">Backup completed</Text>
```

`success`, `warning`, `info` and `destructive` have meanings. `blue`, `green`, `orange` and
`amber` are colour used as data, for example a chart series, a project label or a category.

Use three tones or fewer on one surface. Four or more tones look like a palette, not a set of
meanings. Three tones look like a legend.

Colour is never the full message. Write the words too.

## Same job, same size

On one surface, all controls that do the same job must be the same size. If a row has a size 3
button next to a size 2 button, the two look like different kinds of control. You must then
find the reason.

Also match controls to their surface. A size 3 dialog holds size 3 fields and size 3 buttons.
A control that is two steps smaller than its container looks like a mistake.

## Write the real words

Put real content into a layout. If the real content does not exist yet, write text of the same
shape and length.

Placeholder text hides problems like these:

- a heading that wraps onto three lines on a phone
- a name that is longer than its column
- a button label that changes the rhythm of a row

This rule also applies to helper text. Keep a line if it changes what a person does next.
Delete a line if it only repeats the label.

## Run the reviewer

Before you ship a real screen, run the reviewer on it. Each rule on this page is a live check
in the builder. Each finding quotes the sentence that it comes from, and each finding offers a
fix.

Every template in the builder passes all of these rules. So if a new rule were impossible to
satisfy, the templates would fail on the day that the rule was added.

The reviewer does not tell you whether a screen is good. It tells you whether a screen breaks a
rule that this system has already decided.
