Navigation answers two questions: where can I go, and where am I now. `Shell` answers the first
question with a frame of named regions. Some small decisions answer the second question. Most of
those decisions are about how the app announces the answer, not how it paints it.

## The frame is a pattern, not a component

`Shell` arranges things that it does not own. That makes it a pattern. A component contains the
things that it owns. If a child must reach up and configure its parent, you have built a
pattern as a component.

Each pane has its own `open` state, the same as `Dialog`. Nothing examines the children, and no
pane closes a different pane. Only a `ShellTrigger` crosses the frame. It finds a pane by name.

An app frame sets no height. By default, a `Shell` fills the window. On a phone, the page itself
scrolls, so the browser can make its toolbars smaller. If a `Shell` is inside something else,
such as a demo in a card, set `contained`. Then the `Shell` gets its height from its parent.

```tsx
<Shell size="2">
  <ShellHeader>…</ShellHeader>
  <ShellRail aria-label="Sections">…</ShellRail>
  <ShellSidebar aria-label="Pages">…</ShellSidebar>
  <ShellContent>…</ShellContent>
  <ShellInspector>…</ShellInspector>
</Shell>
```

## The panes

The header is always full width. A header that is not full width is a header inside the
content, and that is a different thing. You can have a sidebar that runs the full height, under
a header that covers only the content. For this layout, do not write a `ShellHeader`. Put a
header inside `ShellContent`.

The rail and the sidebar are two independent columns:

- The rail is the narrow column of icons. It selects a high-level area.
- The sidebar is the wide column. It shows the content of the area that the rail selected.

The two columns can both be present, and neither one collapses into the other. A sidebar holds
many items, and a rail holds a few. One column of navigation is a sidebar. A column of icons
only is a rail. VS Code and Slack use both together.

`ShellContent` renders `<main>`. It is the only pane that you must have. `ShellInspector` is the
detail column on the right. `ShellBottom` is a drawer for a terminal or a log. These two panes
are closed at the start, because people ask for detail when they need it.

`ShellScroll` marks the one part of a pane that scrolls. Everything else in that column stays
where it is, because it is a usual child of the pane. So a pinned header and a pinned footer in
a sidebar are siblings. They are not special parts.

## A pane pads its own content

Each pane is a surface, and it has padding like a surface. Its `size` sets the padding. Do not
add your own `p` or `px` to the first child of a pane. That adds a second inset to the inset
that is already there.

The same rule sets the height of the header. The header holds one row of controls at the size of
the pane, inside the padding of the pane. So at a given size, a header is exactly as tall as the
rail is wide. This height is a minimum, not a fixed height. Taller content makes the header
taller. Shorter content is centred in it.

Two things still go to the edges of the pane. Both do this automatically:

- **A `ShellScroll` goes to the edges without help.** It is a scroll area. A scroll area that is
  directly inside a surface extends to the edges of that surface. It then adds padding to its
  own contents again. So a highlighted navigation row can extend across its full column.
- **For anything else, set `m="bleed"`.** Examples are a picture across the top of the content
  pane, or a canvas that needs the full box. `m="bleed"` cancels the padding of the pane. Any
  surface takes the same value.

```tsx
<ShellContent>
  <Box m="bleed">
    <canvas />
  </Box>
</ShellContent>
```

## An untouched pane decides for itself

If nobody has touched a pane, its state is `auto`. CSS decides what `auto` means at the current
window size. So the first paint is correct on the server and in the browser, with no script.
Both produce the same attribute, so React does not report a difference between them. When a
person first opens or closes a pane, that choice becomes explicit. It then has priority over
the window size.

Nothing in the frame measures anything when it mounts. `useWindowClass()` returns `null` on the
server. It also returns `null` until the first paint, because it does not guess. Use the hook
for decisions after mount. Let the stylesheet set the resting layout of the app.

## Three window sizes, three shapes

A window size selects the shape of the navigation. You decide it one time, at the top of the
app, from the window size. Do not decide it for each container or for each component.

- `narrow` shows one thing at a time. It opens the navigation over the content.
- `regular` keeps the navigation columns in the layout.
- `wide` also keeps them in the layout. It has space for a second column, such as an inspector.

There are three window sizes because navigation has three shapes. A fourth size would ask how
much space a pane has. Container sizes already answer that question.

## Tabs or a segmented control

Both draw a row of choices, and they are two different things. Think about what each one does
without the other. You can switch views without setting a value. You can set a value without
switching a view. **Use `Tabs` when the content under the row changes.**

The difference is in the markup, not only in the paint. A segmented control is a real radio
group. It announces itself as a radio group. Its arrow keys select a value when they move focus.
Its value is sent with a form. A tab bar announces a tab list, and it owns the panels.

```tsx
<SegmentedControl defaultValue="grid" aria-label="Layout">
  <SegmentedItem value="grid">Grid</SegmentedItem>
  <SegmentedItem value="list">List</SegmentedItem>
</SegmentedControl>
```

Formatting buttons are neither of these. If italic and underline can both be on at the same
time, you need a set of toggle buttons. That is a third thing. A radio group holds one answer,
so it cannot show two answers at the same time.

## Menu or select

The same test separates these two. A `Menu` is a list of actions. When you choose an action, it
runs, and the panel closes. A `Select` is a list of values. When you choose a value, it goes into
a control that is sent with a form. A select renders a hidden input and announces itself as a
combobox. A menu with a custom style cannot do that.

This has two results:

- A select puts its panel so that the chosen row is on top of the value that it replaces. So
  the panel can extend both above and below the trigger.
- If nobody has opened a select, it needs `items` to change its value into a label. The labels
  are on options that have not mounted yet.

## Say where you are

Set `current` on a navigation row or on a rail square. It changes the colour of the row. It also
sets `aria-current="page"`. Both halves are important. Colour alone gives no information to a
person who cannot see it. The announcement works with a screen reader, with a high-contrast
setting and on a monochrome display.

```tsx
<Shell size="2">
  <ShellHeader>
    <Flex align="center" gap="3">
      <ShellTrigger target="sidebar" render={<Button size="1" emphasis="quiet" />}>
        Menu
      </ShellTrigger>
      <Text size="2" weight="medium">Kookie Studio</Text>
    </Flex>
  </ShellHeader>

  <ShellSidebar aria-label="Pages">
    <ShellScroll>
      <ShellNavGroup label="Workspace">
        <ShellNavItem current render={<a href="/inbox" />}>Inbox</ShellNavItem>
        <ShellNavItem render={<a href="/drafts" />}>Drafts</ShellNavItem>
        <ShellNavItem render={<a href="/archive" />}>Archive</ShellNavItem>
      </ShellNavGroup>
    </ShellScroll>
  </ShellSidebar>

  <ShellContent>
    <ShellScroll>{children}</ShellScroll>
  </ShellContent>
</Shell>
```

The colour comes from a tone and a loudness. It does not come from a louder step on one scale.
Grey means that your pointer is on the row. Accent means that you are at this location. The two
states use different colours, so the current row still changes when the pointer is on it.

Rows never rank against each other, because every item in a list of locations has the same
importance. The component sets "current" as a state. It is not a loudness that you select.
