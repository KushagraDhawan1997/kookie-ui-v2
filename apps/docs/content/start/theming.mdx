A `Theme` sets eight things for your whole app: appearance, density, radius, contrast,
pointer, depth, material, and size. Every component inside the theme picks up those settings.
All eight are optional, and the defaults suit an app that hasn't made any decisions yet.

## The eight settings

```tsx
<Theme
  appearance="inherit" // inherit | light | dark
  density="default" // compact | default | comfortable
  radius="full" // none | small | medium | large | full
  contrast="normal" // normal | high
  pointer="auto" // fine | coarse | auto
  depth="elevated" // flat | elevated
  material="solid" // solid | thin | regular | thick
  size="2" // 1 | 2 | 3 | 4
>
  {children}
</Theme>
```

### Appearance

`appearance` takes `light`, `dark`, or `inherit`. Use `inherit` at the root. The theme then
reads the mode from `<html>`, where the script in the [Installation](/start/installation)
chapter already wrote it.

### Density

`density` takes `compact`, `default`, or `comfortable`. It changes how much space sits between
elements, and it doesn't shrink anything. A compact theme uses smaller gaps from the same set
of spacing values. Text stays the same size, and corners keep their shape.

### Radius

`radius` takes `none`, `small`, `medium`, `large`, or `full`. Each kind of component works out
its own corner from that one word, so a button, a card, and a menu row stay in proportion at
every setting.

### Contrast

`contrast` takes `normal` or `high`. Set `high` yourself, or leave it alone. Anyone who has
asked their operating system for more contrast gets it automatically.

### Pointer

`pointer` takes `fine`, `coarse`, or `auto`, and tells the theme whether people are using a
mouse or a touch screen. `auto` follows the device. Set it yourself to check phone sizing on
your laptop.

### Depth

`depth` takes `flat` or `elevated`, and decides whether surfaces cast shadows. You decide
once for the whole app, and no component takes a shadow prop.

### Material

`material` takes `solid`, `thin`, `regular`, or `thick`. Material is what your app is made
of. One value covers everything, because every panel in an app is made of the same material.

### Size

`size` takes `1`, `2`, `3`, or `4`, and sets the default size for controls and surfaces. Set it
to `3` and every button, field, card, menu, and dialog that doesn't state a size of its own
moves up one step together. It's a default rather than a limit. A `size` on any component
still wins, and a `Field` or a `Composer` sets the size for the controls inside it, because you
size those as one object.

Size doesn't touch text. `Text` and `Heading` use a nine-step scale of their own, so one number
can't mean the same thing to both. The [Composition](/patterns/composition) chapter covers how
to rank your text. `Code`, `Kbd`, `Badge`, `Avatar`, and `Chip` take the size of the line they
sit in, and this setting leaves them there.

## Nest a Theme to change one region

A Theme inside a Theme changes only the settings it names and inherits the rest.

```tsx
<Theme density="comfortable">
  <Page />
  {/* A dense region inside a roomy app. Nothing else changes. */}
  <Theme density="compact">
    <DataTable />
  </Theme>
</Theme>
```

Use this when one region genuinely needs to behave differently: a dark hero on a light page, a
tight inspector panel in a roomy app, or a glass panel sitting over a photograph.

Nesting also keeps menus and dialogs correct. Every floating layer applies the theme again
inside itself, so a menu opened from a dark section opens dark.

Nesting doesn't affect responsive behaviour. If you want a component to respond to the width
of its container rather than the window, wrap it in `<Box container>`.

## The accent colour

There's no `accentColor` prop. You set your accent in the colour config as a hue and a
saturation, and the generator calculates every shade, every role, both modes, and every
contrast level from those two numbers. A prop could only take a hex value, and a hex value
can't tell the generator what its hover state, its border, or its readable text colour should
be.

So an app has one accent. You can't give one section its own branding today.

## Reading the theme in JavaScript

Components pick up the settings through CSS, so most code never needs to read them. Two hooks
exist for the cases CSS can't reach.

```tsx
import { useMaterial, useWindowClass } from "@kookie-ui/react";

// Your own panel, made of whatever the app is made of.
function Pane({ children }: { children: React.ReactNode }) {
  return (
    <div className="kui-surface" data-material={useMaterial()}>
      {children}
    </div>
  );
}

// Which navigation shape to show.
function Nav() {
  const windowClass = useWindowClass(); // "narrow" | "regular" | "wide" | null
  return windowClass === "narrow" ? <BottomTabs /> : <Sidebar />;
}
```

`useWindowClass` returns `null` on the server and until the first paint, because the server
can't measure a window, and a hook that guessed would make React complain that the server and
browser disagree. If you need the answer before anything paints, write it in CSS instead. The
same breakpoints are exported as `windowClassQueries`.

## Why depth starts elevated and material starts solid

**`depth` starts at `elevated`** because most apps have a light source. A flat app is a
deliberate choice, so you state it.

**`material` starts at `solid`.** Solid is the setting where light stops passing through.
Glass only appears when the theme is made of glass and something is behind the panel to bend,
so a control in ordinary page flow stays solid.
