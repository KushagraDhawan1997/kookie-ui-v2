A `Theme` sets eight settings for your whole app: appearance, density, radius, contrast,
pointer, depth, material, and size. Each component inside the theme uses those settings. All
eight settings are optional. The default values are correct for an app that hasn't made any
decisions yet.

## The eight settings

```tsx
<Theme
  appearance="inherit" // inherit | light | dark
  density="default" // compact | default | comfortable
  radius="full" // none | small | medium | large | full
  contrast="normal" // normal | high
  pointer="auto" // fine | coarse | auto
  depth="elevated" // flat | elevated
  material="solid" // solid | thin | regular | thick
  size="2" // 1 | 2 | 3 | 4
>
  {children}
</Theme>
```

### Appearance

`appearance` takes `light`, `dark`, or `inherit`. Use `inherit` at the root. The theme then
gets the mode from `<html>`. The script in the [Installation](/start/installation) chapter
writes the mode there.

### Density

`density` takes `compact`, `default`, or `comfortable`. It changes the space between elements.
It doesn't make elements smaller. A compact theme uses smaller gaps from the same set of spacing
values. Text keeps its size, and corners keep their shape.

### Radius

`radius` takes `none`, `small`, `medium`, `large`, or `full`. The theme calculates a different
corner for each kind of component from that one value. Thus a button, a card, and a menu row
stay in proportion at each setting.

### Contrast

`contrast` takes `normal` or `high`. You can set `high` yourself, or you can leave the default.
If a person sets more contrast in their operating system, they get high contrast
automatically.

### Pointer

`pointer` takes `fine`, `coarse`, or `auto`. It tells the theme if people use a mouse or a
touch screen. `auto` follows the device. To check the phone sizes on your laptop, set it
yourself.

### Depth

`depth` takes `flat` or `elevated`. It sets whether surfaces cast shadows. Set it one time
for the whole app. No component has a shadow prop.

### Material

`material` takes `solid`, `thin`, `regular`, or `thick`. The material is what your app is
made of. One value applies to all panels, because all panels in an app use the same
material.

### Size

`size` takes `1`, `2`, `3`, or `4`. It sets the default size for controls and surfaces. If you
set it to `3`, each button, field, card, menu, and dialog without its own size moves up one
step. This setting is a default, not a limit. A `size` on a component always wins. A `Field`
or a `Composer` sets the size for the controls inside it. You size those controls as one
object.

The `size` setting doesn't change text. `Text` and `Heading` use their own scale of nine steps.
Thus one number can't have the same meaning for both scales. The
[Composition](/patterns/composition) chapter shows how to rank your text. `Code`, `Kbd`,
`Badge`, and `Chip` use the size of the line that they are in. This setting doesn't change
them. `Avatar` follows this setting, as a control does.

## Nest a Theme to change one region

A Theme inside a Theme changes only the settings that it names. It inherits the other
settings.

```tsx
<Theme density="comfortable">
  <Page />
  {/* A dense region inside a roomy app. Nothing else changes. */}
  <Theme density="compact">
    <DataTable />
  </Theme>
</Theme>
```

Use a nested Theme when one region must behave differently. For example:

- a dark hero on a light page
- a compact inspector panel in a comfortable app
- a glass panel over a photograph

Nesting also keeps menus and dialogs correct. Each floating layer applies the theme again
inside itself. Thus a menu that opens from a dark section is also dark.

Nesting doesn't change responsive behaviour. To make a component respond to the width of its
container, not the window, wrap it in `<Box container>`.

## The accent colour

There's no `accentColor` prop. Set your accent in the colour config as a hue and a
saturation. From those two numbers, the generator calculates:

- each shade and each colour role
- both modes
- each contrast level

A prop could only take a hex value. A hex value can't tell the generator the correct hover
colour, border colour, or text colour.

Thus an app has one accent. You can't give one section a different brand colour.

## Read the theme in JavaScript

Components get the settings through CSS, so most code never reads them. For the cases that
CSS can't do, use one of two hooks.

```tsx
import { useMaterial, useWindowClass } from "@kookie-ui/react";

// Your own panel, made of whatever the app is made of.
function Pane({ children }: { children: React.ReactNode }) {
  return (
    <div className="kui-surface" data-material={useMaterial()}>
      {children}
    </div>
  );
}

// Which navigation shape to show.
function Nav() {
  const windowClass = useWindowClass(); // "narrow" | "regular" | "wide" | null
  return windowClass === "narrow" ? <BottomTabs /> : <Sidebar />;
}
```

`useWindowClass` returns `null` on the server and until the first paint. The server can't
measure a window. If the hook guessed, React would report that the server and the browser do
not agree. If you need the answer before the first paint, write it in CSS. The package exports
the same breakpoints as `windowClassQueries`.

## Why depth starts elevated and material starts solid

**`depth` starts at `elevated`** because most apps have a light source. A flat app is a
deliberate choice, so you set it yourself.

**`material` starts at `solid`.** With `solid`, no light goes through a panel. Glass shows only
when two conditions are true: the theme is glass, and there is something behind the panel to
bend. Thus a control in the normal page flow stays solid.
