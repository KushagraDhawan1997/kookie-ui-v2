Most interface problems are already solved. An AI agent can find the answer, but building
something new is faster, so each screen gets a slightly different answer. Kookie puts the
answers into the components, so the right one is the one you get without asking.

## Learn from Apple

Kookie takes its method from Apple's Human Interface Guidelines. Every rule has three parts:

- **A question:** Is this navigation or an action? Can the person undo it?
- **A reason:** a measured limit, or a judgment that is said to be one.
- **A default:** a component that already follows the rule.

Apple can enforce its defaults because it makes the operating system. Kookie enforces them
through TypeScript: a prop that Kookie does not accept is a compile error that says what to
write instead.

## Measured limits and judgments

Where research gives an answer, Kookie applies it and no prop overrides it. A touch target is
at least 44 pixels on a touch screen. Text meets WCAG and APCA contrast.

Corner radius, the accent hue and card padding have no measured answer. Each is a judgment,
stored once, so one edit changes it everywhere.

## Answer each question once

A component takes a meaning, not a value. There is no `variant` prop and no margin prop.

```tsx
<Button tone="destructive" emphasis="loud">
  Delete project
</Button>
```

## Choose a component by its job

Start with what the person is doing, and the job gives you a short list. The
[Vocabulary](/start/vocabulary) chapter lists the jobs.

<Example name="principles.lookalikes" quiet />

`Tabs` and `SegmentedControl` look alike. `Tabs` moves you to another view. A
`SegmentedControl` sets a value and leaves the content in place.

## Undo instead of warning

If an action can be undone, do it and offer a way back. Use an `AlertDialog` only for a loss
that cannot be undone. A frequent warning teaches people to press OK without reading.

## Keep people oriented

- **Dim, don't hide:** An unavailable action stays visible and disabled.
- **One dialog at a time:** A dialog over a dialog hides the task that opened it.
- **No hidden-only commands:** Every action in a `ContextMenu` must also be reachable another
  way.
- **Same features at every size:** A narrow window shows less at once, but removes nothing.

## The trade-off

Kookie gives you fewer overrides. In return, your screens stay consistent as the app grows.
`style` and `className` remain available, and both are easy to find in a review.
