Kookie uses a small set of categories to define components: grounds, cards, controls, marks, and
rows. A component's category determines which props it accepts.

For example, a `Card` accepts a material prop because it is a surface, while a `Checkbox` does
not because a mark has no surface. Similarly, a `Button` accepts `emphasis` because actions rank
against each other, whereas a `MenuItem` does not because menu items hold equal weight.

If a component lacks a prop you expect, its category usually explains why. Each component page
also lists the props the component refuses, along with the reasoning.

## Grounds, cards and the page

A screen consists of three levels:

- **The page:** The bottom level. Kookie never paints the page background to avoid repainting
  for every nested theme; your application sets this colour. The [Colour](/foundations/color)
  chapter provides the values.
- **A ground:** A region that holds other elements, such as a `Surface`. Its colour sits close to
  the page, and it casts no shadow because it belongs to the page rather than sitting above it.
- **A card:** An object with its own surface. A `Card` is opaque, hiding anything behind it. In a
  raised theme, a card casts a shadow.

## Controls

A control is an interactive element. Every control shares the same states, size steps, and
loudness settings. Kookie features four categories:

- **Buttons:** Perform an action and rank against each other. `emphasis` sets the visual weight
  relative to nearby actions, while `tone` defines the action's meaning.
- **Fields:** Hold user input. Fields do not rank against each other, so `TextField` and
  `TextArea` do not accept `emphasis` or `tone`. Because a field is a recess rather than a raised
  object, it never casts a shadow.
- **Marks:** Small controls without text, such as `Checkbox`, `Radio`, the `Switch` track, and the
  `Slider` handle. A mark sits beside its label, ignoring control height to measure exactly one
  line of the adjacent text. Marks do not accept a `label` prop, as `Text` already provides the
  necessary styling.
- **Instruments:** Display a value on a track, such as `Slider` and `Progress`. Instruments have
  no surface or border, so they do not accept material or surface styling.

## Rows

A row is a single interactive line in a list, such as `Row`, `MenuItem`, or a line in a
`NavTree`.

While a row resembles a small button, list options do not outrank one another, so rows do not
accept `emphasis`. A selected row changes colour rather than becoming visually louder.

Row height depends on context. In a permanent column like a sidebar, a row matches the height of
a `Button` at the same size. In a menu or select, a row is shorter, measuring one line of text
with minimal padding.

## Type, layout and the frame

Type components derive their colour from the surface beneath them. `Text`, `Heading`,
`Blockquote`, `Code`, and `Kbd` have no fill, so `emphasis` adjusts the text colour rather than
the background.

`Link` is interactive but is considered type, not a control. While a control is a distinct box
with padding and a tap target, a link is a group of words within a sentence. It must remain
selectable, wrap across lines, and sit inline with paragraph text, providing hover and focus
states without a bounding box.

Layout components do not render visually. `Box` handles the core functionality, while `Flex`,
`Stack`, and `Grid` are specialised Box components with fixed displays and streamlined props.

The frame is the `Shell`, which is a pattern rather than a component. It arranges the header,
sidebar, and content without owning them. The [Principles](/start/principles) chapter explains
the difference between components and patterns.

## Which word to use

The following pairs share an appearance but belong to different categories and serve distinct
purposes:

- **Tabs or SegmentedControl:** A tab bar changes the content below it. A segmented control sets
  a value in place.
- **Dialog or AlertDialog:** A dialog holds requested work. An alert interrupts the user with a
  single question, and Kookie manages its layout.
- **Menu or Select:** A menu triggers an action. A select chooses a value to submit with a form.
- **Link or Button:** A link navigates to a new address, while a button executes a function. Use
  a quiet Button if an action must look like plain text.
- **Card or Surface:** A card is an independent object. A surface is the background that objects
  sit on.
- **Popover or Dialog:** A popover keeps the underlying page active, while a dialog dims the
  application and traps focus. Choose based on whether the rest of the app must remain
  interactive.
- **Popover or Tooltip:** A popover opens on a press and holds arbitrary content. A tooltip
  appears on hover and holds a single sentence. Because keyboard and touch users may never see a
  tooltip, it should only repeat what the control already announces.
