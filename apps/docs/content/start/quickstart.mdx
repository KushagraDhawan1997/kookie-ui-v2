You'll build a publish dialog one piece at a time. Each piece runs next to the code that makes it.
At the end, you'll have written no colours, no pixel values and no breakpoints.

## Choose the containers before the components

The container sets the distance between its children. So the first decision is which container
controls which spacing.

<Example name="quickstart.containers" />

The two Stacks use different gaps. The outer Stack uses gap 6, which separates whole sections.
The inner Stack uses gap 2, which keeps the heading near the sentence below it.

Keep related elements closer together than unrelated elements. If a screen uses the same gap
everywhere, it looks like one long list.

Nothing in that file sets a margin. No component sets its own outer spacing. So each distance on
the screen comes from a container that you can see.

## Put a checkbox beside its label

<Example name="quickstart.group" />

These controls are checkboxes, not switches. A switch applies its value immediately when you
change it. So a screen of switches needs no Save button. A checkbox holds a value that you will
submit later. These two checkboxes wait for the Publish button.

No checkbox or switch takes a `label` prop. A label is text, and `Text` already gives every size,
weight and colour that text needs. A `label` prop on a checkbox would add a second, smaller text
system inside the checkbox.

`render={<label htmlFor="…" />}` changes the element and keeps the component. You keep the text
size and colour. The browser gets a real `<label>`, so a click on the words toggles the control.

The outer Stack uses gap 5, not gap 4. Stacked checkboxes and switches need 12 real pixels
between them. The tap target of each control is larger than the mark that you can see. Below 12
pixels, the targets overlap. Then a click on one row can toggle the row above it.

## Rank the two buttons

<Example name="quickstart.actions" />

Two props do two different jobs here. `emphasis` sets how much attention the button asks for:
`quiet`, `medium` or `loud`. `tone` sets what the button means. Because the two props are
separate, no value such as `secondary-outline-destructive` exists. That one string gives three
answers at the same time. You can't change one answer without a change to the other answers.

No button is loud and accent by default. You must choose a second loud button on purpose. So
most screens have one clear action.

## What you never had to write

The finished file is about fifty lines. It contains none of the items below.

- **No colours.** You selected a tone and an emphasis, and the theme calculated the colours. The
  result follows dark mode and responds to the high-contrast setting. It stays correct if you
  change the accent later.
- **No pixel sizes.** `size` is a step. One number sets the height, the padding, the corner, the
  icon and the label size together.
- **No breakpoints.** Targets become larger on a touch screen, and text becomes larger on a
  phone. Layouts respond to the space that they get, not to the width of the window.
- **No hover, focus or press styles.** CSS controls every state. So no JavaScript runs when
  someone points at a control.
- **No accessibility wiring other than `htmlFor`.** The roles, the keyboard behaviour and the
  announcements come with the components.
