You'll build a publish dialog one piece at a time, with each piece running next to the code that
makes it. By the end you will have written no colours, no pixel values and no breakpoints.

## Choose the containers before the components

The container sets the distance between its children, which makes the first decision a question
of who controls which spacing.

<Example name="quickstart.containers" />

The two Stacks use different gaps. The outer Stack takes gap 6, which separates whole sections,
while the inner Stack takes gap 2, which keeps the heading near the sentence below it.

Keep related elements closer together than unrelated ones, because a screen that uses the same
gap everywhere reads as one long list.

Nothing in that file sets a margin, since no component sets its own outer spacing, so every
distance on the screen comes from a container you can see.

## Put a checkbox beside its label

<Example name="quickstart.group" />

These controls are checkboxes rather than switches. A switch applies its value the moment you
change it, so a screen of switches needs no Save button, whereas a checkbox holds a value that
you submit later. These two checkboxes wait for the Publish button.

No checkbox or switch accepts a `label` prop, because a label is text and `Text` already provides
every size, weight and colour that text needs. A `label` prop would add a second, smaller text
system inside the checkbox.

`render={<label htmlFor="…" />}` changes the element while keeping the component, so you keep the
text size and colour and the browser receives a real `<label>`, which makes a click on the words
toggle the control.

The outer Stack takes gap 5 rather than gap 4, because stacked checkboxes and switches need 12
real pixels between them. Each control's tap target is larger than the mark you can see, so below
12 pixels the targets overlap and a click on one row can toggle the row above it.

## Rank the two buttons

<Example name="quickstart.actions" />

Two props do two different jobs here. `emphasis` sets how much attention the button asks for,
taking `quiet`, `medium` or `loud`, while `tone` sets what the button means. Keeping the two
separate is why no value such as `secondary-outline-destructive` exists: that single string
answers three questions at once, and you cannot change one answer without changing the others.

No button is loud and accent by default, so a second loud button is always a deliberate choice,
which leaves most screens with one clear action.

## What you never had to write

The finished file runs to about fifty lines and contains none of the following.

- **No colours.** You selected a tone and an emphasis, and the theme calculated the colours,
  which follow dark mode, respond to the high-contrast setting, and stay correct if you change
  the accent later.
- **No pixel sizes.** `size` selects a step, and one number sets the height, the padding, the
  corner, the icon and the label size together.
- **No breakpoints.** Targets grow on a touch screen and text grows on a phone, while layouts
  respond to the space they receive rather than to the width of the window.
- **No hover, focus or press styles.** CSS resolves every state, so no JavaScript runs when
  somebody points at a control.
- **No accessibility wiring beyond `htmlFor`.** The roles, the keyboard behaviour and the
  announcements arrive with the components.
