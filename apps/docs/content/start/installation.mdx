Setting up takes three steps: adding the package, importing one stylesheet, and wrapping your
app in a `Theme`. There's no config file or build plugin, because the package calculates every
value beforehand and ships it as a CSS custom property.

## Add the package

`@kushagradhawan/kookie-ui-react` is pre-release and not yet published to npm, so build it from the repository
for now:

```bash
git clone https://github.com/KushagraDhawan1997/kookie-ui-v2
cd kookie-ui-v2
pnpm install
pnpm run build
```

Then add it as a dependency of an app in the same workspace:

```json title="package.json"
{
  "dependencies": {
    "@kushagradhawan/kookie-ui-react": "workspace:*"
  }
}
```

Once the package reaches npm you will install it with `pnpm add @kushagradhawan/kookie-ui-react`, and the
other setup steps stay the same. Kookie requires React 19 and React DOM 19.

## Import the stylesheet once

```tsx
import "@kushagradhawan/kookie-ui-react/styles.css";
```

Import it at the root of your app, since this single file contains every style:

- the colour and spacing values
- the shared rules for controls
- the rules for each component

## Wrap your app in a Theme

```tsx
import "@kushagradhawan/kookie-ui-react/styles.css";
import { Theme } from "@kushagradhawan/kookie-ui-react";

export default function App({ children }: { children: React.ReactNode }) {
  return <Theme>{children}</Theme>;
}
```

`Theme` holds eight settings for your app: appearance, radius, density, depth, material, size,
contrast, and pointer. Every component inside it reads those settings, and the
[Theming](/start/theming) chapter explains each one.

## Set the page background

The library paints no background of its own, so set one in your own CSS:

```css
body {
  margin: 0;
  min-height: 100dvh;
  background: var(--color-page);
  color: var(--color-text);
  font-family: var(--font-body);
}
```

Use `--color-ground` instead when your page holds mostly cards. It sits slightly darker than
the page in light mode and slightly lighter in dark mode, which gives the cards a background
that differs from their own fill.

## Set dark mode before the page paints

Your server cannot know whether to render light or dark, because a saved preference and the
operating system setting both live in the browser. A guess produces one of two problems:

- The page shows the wrong colours for a short time.
- React reports that the server and the browser disagree.

To prevent both, put a small script in your `<head>` that writes the mode onto `<html>` before
the page paints, then set your root `Theme` to `appearance="inherit"`, which tells the Theme not
to write an appearance of its own.

```html
<script>
  (function () {
    var e = document.documentElement;
    var read = function (k) {
      try { return localStorage.getItem(k); } catch (err) { return null; }
    };
    var a = read("kui-appearance");
    var dark = a === "light" ? false
      : a === "dark" ? true
      : matchMedia("(prefers-color-scheme: dark)").matches;
    e.setAttribute("data-appearance", dark ? "dark" : "light");
    var c = read("kui-contrast");
    if (c === "high" || c === "normal") e.setAttribute("data-contrast", c);
  })();
</script>
```

```tsx
<html lang="en" suppressHydrationWarning>
  <head>{/* the script above */}</head>
  <body>
    <Theme appearance="inherit">{children}</Theme>
  </body>
</html>
```

Two details in that script matter, and both are easy to get wrong.

**Put the `try` around the read, not around the whole function.** Some browsers throw when you
read `localStorage`, and Safari throws when a person blocks all cookies. A `try` that wraps the
whole function also skips the two `setAttribute` calls, which gives a person with a dark
operating system a light page. The media query never throws, so keep the writes outside the
`try`.

**Write both attributes onto the same element.** The high-contrast colours apply only when
`data-appearance` and `data-contrast` sit on the same element, so a script that sets the
appearance must also set the contrast.

## Point the font tokens at your fonts

The library ships no font files, and it reads three font tokens. Point them at the fonts that
your app serves:

```css
:root {
  --font-body: "Inter", system-ui, sans-serif;
  --font-heading: var(--font-body);
  --font-mono: "Berkeley Mono", ui-monospace, monospace;
}
```

The tokens fall back to the system fonts if you leave them unset.

## Check that it worked

```tsx
import { Button, Card, Stack, Text } from "@kushagradhawan/kookie-ui-react";

export function Smoke() {
  return (
    <Card size="3">
      <Stack gap="3">
        <Text>The card around this text has a corner, a fill, and a border.</Text>
        <Button tone="accent" emphasis="loud">Everything is wired up</Button>
      </Stack>
    </Card>
  );
}
```

The stylesheet and the Theme both work if the card shows rounded corners and the button shows
your accent colour.
