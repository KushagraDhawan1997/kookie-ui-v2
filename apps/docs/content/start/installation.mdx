KookieUI needs three things: the package, one stylesheet, and a `Theme` wrapped around your
app. There is no config file and no build plugin. Every value is worked out ahead of time and
shipped as CSS custom properties.

## The package is not on npm yet

`@kookie-ui/react` is pre-release, so you cannot install it from npm today. Build it from the
repository instead:

```bash
git clone https://github.com/KushagraDhawan1997/kookie-ui-v2
cd kookie-ui-v2
pnpm install
pnpm run build
```

Then depend on it from an app in the same workspace. This site does exactly that:

```json title="package.json"
{
  "dependencies": {
    "@kookie-ui/react": "workspace:*"
  }
}
```

Once it is published, you will install it with `pnpm add @kookie-ui/react` and nothing else on
this page will change. You need React 19 and React DOM 19.

## Import the stylesheet once

```tsx
import "@kookie-ui/react/styles.css";
```

Import it one time, at the root of your app. This single file contains everything: the colour
and spacing values, the shared rules for controls, and the rules for every component. There is
no separate stylesheet per component.

The file is the same size no matter how many components you use, so adding a component
tomorrow costs you no extra CSS.

## Wrap your app in a Theme

```tsx
import "@kookie-ui/react/styles.css";
import { Theme } from "@kookie-ui/react";

export default function App({ children }: { children: React.ReactNode }) {
  return <Theme>{children}</Theme>;
}
```

`Theme` is where your app's seven settings live: appearance, radius, density, depth, material,
contrast and pointer. Everything inside it picks up those settings automatically. See
[Theming](/start/theming) for what each one does.

## Paint the page yourself

The library does not set a background colour on your page, because a Theme that painted one
would repaint it again every time you nested another Theme inside it. Set it in your own CSS:

```css
body {
  margin: 0;
  min-height: 100dvh;
  background: var(--color-page);
  color: var(--color-text);
  font-family: var(--font-body);
}
```

Use `--color-ground` instead of `--color-page` if your page is mostly cards. It steps away from
the page in both modes — darker in light, lighter in dark — so the cards on it have something to
sit on.

## Set dark mode before the page paints

Your server cannot know whether to render light or dark. Whether someone chose a mode, and
what their operating system prefers, are both things only their browser knows. If the server
guesses, you get one of two problems: the page flashes the wrong colours, or React complains
that the server and browser disagree.

The fix is a small script in your `<head>` that writes the answer onto `<html>` before
anything paints. Then set your root `Theme` to `appearance="inherit"` so it does not write an
appearance of its own, and one element holds the answer.

```html
<script>
  (function () {
    var e = document.documentElement;
    var read = function (k) {
      try { return localStorage.getItem(k); } catch (err) { return null; }
    };
    var a = read("kui-appearance");
    var dark = a === "light" ? false
      : a === "dark" ? true
      : matchMedia("(prefers-color-scheme: dark)").matches;
    e.setAttribute("data-appearance", dark ? "dark" : "light");
    var c = read("kui-contrast");
    if (c === "high" || c === "normal") e.setAttribute("data-contrast", c);
  })();
</script>
```

```tsx
<html lang="en" suppressHydrationWarning>
  <head>{/* the script above */}</head>
  <body>
    <Theme appearance="inherit">{children}</Theme>
  </body>
</html>
```

Two details in that script matter, and both are easy to get wrong.

**Put the `try` around the read, not around everything.** Some browsers throw an error just
for reading `localStorage`. Safari does it when someone blocks all cookies. If you wrap the
whole function in one `try`, that error also skips the two `setAttribute` calls, and someone
with a dark operating system gets a light page. Reading the media query never throws, so guard
the read and leave the writes outside.

**Write both attributes onto the same element.** The high-contrast colours only apply when
`data-appearance` and `data-contrast` are on one element together. If your script takes over
the appearance, it has to take over the contrast as well.

## Point the font tokens at your fonts

The library ships no font files. It reads three tokens, so point them at whatever you serve:

```css
:root {
  --font-body: "Inter", system-ui, sans-serif;
  --font-heading: var(--font-body);
  --font-mono: "Berkeley Mono", ui-monospace, monospace;
}
```

If you set nothing, they fall back to the standard system fonts.

## Check that it worked

```tsx
import { Button, Card, Stack, Text } from "@kookie-ui/react";

export function Smoke() {
  return (
    <Card size="3">
      <Stack gap="3">
        <Text>This card has a corner, a fill and a border when the stylesheet loads.</Text>
        <Button tone="accent" emphasis="loud">The only loud control on this screen</Button>
      </Stack>
    </Card>
  );
}
```

If the card has rounded corners and the button shows your accent colour, everything is wired up.
