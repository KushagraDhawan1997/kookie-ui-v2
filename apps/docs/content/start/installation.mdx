Setting up takes three steps: adding the package, importing one stylesheet, and wrapping your
app in a `Theme`. There's no config file or build plugin. The package calculates every value
beforehand and ships it as a CSS custom property.

## Add the package

`@kookie-ui/react` is pre-release, and it isn't on npm yet. For now, build it from the
repository:

```bash
git clone https://github.com/KushagraDhawan1997/kookie-ui-v2
cd kookie-ui-v2
pnpm install
pnpm run build
```

Then add it as a dependency of an app in the same workspace:

```json title="package.json"
{
  "dependencies": {
    "@kookie-ui/react": "workspace:*"
  }
}
```

When the package is on npm, you'll install it with `pnpm add @kookie-ui/react`. The other
setup steps stay the same. You need React 19 and React DOM 19.

## Import the stylesheet once

```tsx
import "@kookie-ui/react/styles.css";
```

Import it at the root of your app. This one file contains all the styles:

- the colour and spacing values
- the shared rules for controls
- the rules for each component

## Wrap your app in a Theme

```tsx
import "@kookie-ui/react/styles.css";
import { Theme } from "@kookie-ui/react";

export default function App({ children }: { children: React.ReactNode }) {
  return <Theme>{children}</Theme>;
}
```

`Theme` holds eight settings for your app: appearance, radius, density, depth, material, size,
contrast, and pointer. Each component inside it uses those settings. The
[Theming](/start/theming) chapter explains each setting.

## Set the page background

The library doesn't paint the background of your page. Set it in your own CSS:

```css
body {
  margin: 0;
  min-height: 100dvh;
  background: var(--color-page);
  color: var(--color-text);
  font-family: var(--font-body);
}
```

If your page holds mostly cards, use `--color-ground` instead. In light mode, it's slightly
darker than the page. In dark mode, it's slightly lighter. The cards then have a background
that is different from their own fill.

## Set dark mode before the page paints

Your server can't know whether to render light or dark. A saved preference and the setting of
the operating system are both in the browser. If the server guesses, you get one of two
problems:

- The page shows the wrong colours for a short time.
- React reports that the server and the browser do not agree.

To prevent this, put a small script in your `<head>`. The script writes the mode onto `<html>`
before the page paints. Then set your root `Theme` to `appearance="inherit"`. This tells the
Theme not to write an appearance of its own.

```html
<script>
  (function () {
    var e = document.documentElement;
    var read = function (k) {
      try { return localStorage.getItem(k); } catch (err) { return null; }
    };
    var a = read("kui-appearance");
    var dark = a === "light" ? false
      : a === "dark" ? true
      : matchMedia("(prefers-color-scheme: dark)").matches;
    e.setAttribute("data-appearance", dark ? "dark" : "light");
    var c = read("kui-contrast");
    if (c === "high" || c === "normal") e.setAttribute("data-contrast", c);
  })();
</script>
```

```tsx
<html lang="en" suppressHydrationWarning>
  <head>{/* the script above */}</head>
  <body>
    <Theme appearance="inherit">{children}</Theme>
  </body>
</html>
```

Two details in that script are important, and it's easy to get them wrong.

**Put the `try` around the read, not around the whole function.** Some browsers throw an error
when you read `localStorage`. For example, Safari throws when a person blocks all cookies. If
one `try` wraps the whole function, the error also skips the two `setAttribute` calls. Then a
person with a dark operating system gets a light page. The media query never throws an error.
So put the `try` around the read only, and keep the writes outside it.

**Write both attributes onto the same element.** The high-contrast colours apply only when
`data-appearance` and `data-contrast` are on the same element. If your script sets the
appearance, it must also set the contrast.

## Point the font tokens at your fonts

The library doesn't ship font files. It uses three font tokens. Set them to the fonts that
your app serves:

```css
:root {
  --font-body: "Inter", system-ui, sans-serif;
  --font-heading: var(--font-body);
  --font-mono: "Berkeley Mono", ui-monospace, monospace;
}
```

If you don't set them, the tokens use the system fonts.

## Check that it worked

```tsx
import { Button, Card, Stack, Text } from "@kookie-ui/react";

export function Smoke() {
  return (
    <Card size="3">
      <Stack gap="3">
        <Text>The card around this text has a corner, a fill, and a border.</Text>
        <Button tone="accent" emphasis="loud">Everything is wired up</Button>
      </Stack>
    </Card>
  );
}
```

If the card has rounded corners and the button shows your accent colour, the stylesheet and
the Theme both work.
