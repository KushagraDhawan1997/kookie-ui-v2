One scale of nine steps sets the size of all text. This includes body copy, headings, button
labels, field values, and code. A step is a position on that scale. It is not a font size. The
heaviest weight is semibold. Thus you rank text by size and colour.

## Text and Heading share one scale

`Text` and `Heading` use the same nine steps with two different fonts. When you select a step,
you set the font size, the line height, and the letter spacing together. There is no single
ratio for line height. One ratio cannot be correct at both ends of a scale from 12 to 56 pixels.

A size means the same thing on both components. `<Text size="6">` and `<Heading size="6">` are
the same step. Only the font and the default weight are different. Button labels use the same
scale. Thus a button and the text next to it always use the same steps.

## Size sets the step, render sets the element

The size of the text and its position in the document outline are two different questions.
Each question has its own prop.

```tsx
// The page title: an h1 in the outline, at the top of the scale
<Heading size="8" render={<h1 />}>Billing</Heading>

// A card title: an h3 in the outline, two steps down
<Heading size="6" render={<h3 />}>Payment method</Heading>
```

By default, `Heading` renders an `<h2>` at size 6, because a page seldom needs a second `<h1>`.
By default, `Text` renders a `<span>` at size 3. If you want a paragraph, write
`render={<p />}`.

There is no `level` or `as` prop that does both jobs. With one prop for both jobs, you must
select between two results. One result is the correct outline for a screen reader. The other
result is the correct size for the design.

## The heaviest weight is semibold

The three weights are `--font-weight-regular`, `--font-weight-medium`, and
`--font-weight-semibold`. The `weight` prop takes those names. It does not take numbers.

There is no bold. The system already has two ways to show that one item is more important than
another. These are the nine steps and the three text colours. A bold face is a third way, and it
is not on either scale. In practice, people put it on everything.

The type does not accept bold, so a bold weight does not compile. The token does not exist. If
your app really needs a bold face, set it with `style`.

Rank with size, and make text quieter with colour:

```tsx
// Not this: a heavier face at the same step
<Heading size="6" weight="semibold">Notifications</Heading>
<Text size="6" weight="medium">Choose what reaches you.</Text>

// This: a real step down, and a quieter colour
<Heading size="6">Notifications</Heading>
<Text size="3" emphasis="medium">Choose what reaches you.</Text>
```

## Three fonts

Your Theme sets `--font-heading`, `--font-body`, and `--font-mono`. Components use one of those
three. They never use a font stack. Thus the Theme is the only place where you write a font
stack.

`Heading` uses the heading font. `Text`, `Blockquote`, and `Link` use the body font. `Code` uses
the mono font at a slightly smaller size. A monospaced face is wider and taller. At the same
size, it looks one step larger.

`Kbd` is the exception: a keycap uses the **body** font. A monospaced ⌘ becomes narrow to fit a
fixed character width. Also, every platform shows shortcuts in its interface font.

## Emphasis picks a text colour

`emphasis` has three different effects. The effect depends on the component:

- On a button, it selects a fill.
- On a card, it selects the styling.
- On text, it selects a colour.

On text, loud is `--color-text`, medium is `--color-text-muted`, and quiet is
`--color-text-faint`. If you add a `tone`, the same three levels move to that colour family.

Text is loud at rest, and this is intentional. Full contrast is the correct default for
reading. A grey paragraph looks optional.

Quiet is below the minimum contrast for body text intentionally. Use it for an item that nobody
must read or act on, such as a disabled option. Do not set a full paragraph in quiet.

## How text responds to the device

Two items change with the device. They are not related, so the system controls them
separately.

- **Reading sizes increase on a touch screen.** Steps 1 to 4 increase, so body copy goes from 16
  to 18 pixels. The reason is distance: you hold a phone near your face. Apple publishes one
  Dynamic Type table for both iPhone and iPad. Thus this rule is the same for a phone and a
  tablet.
- **Display sizes decrease on a narrow window.** Steps 8 and 9 decrease, so a page title goes
  from 56 to 40 pixels. The reason is line length. A 56-pixel title on a 375-pixel screen fits
  approximately seven characters on each line. A narrow browser window on a laptop has the same
  problem.

Each rule changes only the steps that it must change. Thus the two rules do not conflict on a
phone, where both apply. A tablet in landscape gets larger reading text and keeps its full-size
titles. A narrow desktop window gets smaller titles, and the reading text does not change.

You do not have to turn these rules on. A size number names a role, not a pixel value. Thus do
not build a layout on a pixel measurement that you took from a step.

## The five steps to compose with

These five steps are the house style. They are a judgment, not a measurement. Each distance
follows a theme setting, but type has no theme setting. Thus the rule is written here.

**Use these five.** Page title **8**. Section **7**. Card or block title **6**. Body **3**.
Label and small print **2**. A card title over body is 24 pixels over 16 pixels, and that is a
real step down. Steps 4, 5, and 9 are for cases that these five do not cover, such as a hero or
a large number. Use them only for those cases.

**Rank by size, not by weight.** A 16-pixel title over a 14-pixel body is 1.14 times the size.
That difference is too small to look like a hierarchy. Larger steps also have tighter letter
spacing. The spacing is neutral from step 1 to step 3, and it becomes tighter from step 4 up.
Thus a small title never gets the tighter spacing.

**Do not use size 1 on a real screen.** Twelve pixels is only for text at the edge of a screen.
Examples are a footer, a legal line, or the controls of a dense table. If an item is less
important, use the muted or faint colour at 14 or 16 pixels. If a screen needs 12-pixel text to
make space, the problem is the spacing, not the type.

This example shows the five steps together:

```tsx
<Stack gap="6">
  <Heading size="8" render={<h1 />}>Billing</Heading>

  <Stack gap="5">
    <Heading size="7" render={<h2 />}>Payment method</Heading>

    <Card size="3">
      <Stack gap="3">
        <Heading size="6" render={<h3 />}>Visa ending 4021</Heading>
        <Text size="3" render={<p />}>Renews on 3 September for 24 dollars.</Text>
        <Text size="2" emphasis="medium">Updated 3 August</Text>
      </Stack>
    </Card>
  </Stack>
</Stack>
```

The page title, the section, the card title, the body, and the small print are five different
steps. The document outline is also correct, because `render` selected the element and `size`
selected the step.
