All text in Kookie uses one scale of nine steps, from body copy and headings to button labels,
field values and code. You pick a step by number, and the theme decides the font size, line
height and letter spacing for it. Because the heaviest weight is semibold, you rank text with
size and colour rather than with bold.

## Text and Heading use the same steps

`Text` and `Heading` use the same nine steps in two different fonts. A step sets the font size,
the line height and the letter spacing together, and each step is chosen by hand, because no
single ratio for line height works at both ends of a scale that runs from 12 to 64 pixels.

A step means the same thing on both components, so `<Text size="6">` and `<Heading size="6">`
are the same size and differ only in font and default weight. Button labels use the same scale,
which keeps a button and the text beside it in step.

## Size sets the step, render sets the element

How large a heading looks and where it sits in the document outline are separate questions, so
each one has its own prop:

```tsx
// The page title: an h1 in the outline, near the top of the scale
<Heading size="8" render={<h1 />}>Billing</Heading>

// A card title: an h3 in the outline, two steps down
<Heading size="6" render={<h3 />}>Payment method</Heading>
```

`Heading` renders an `<h2>` at size 6 unless you say otherwise, because most headings on a page
are not the page title. `Text` renders a `<span>` at size 3. Write `render={<p />}` when you
want a paragraph.

There is no `level` or `as` prop that sets both at once, because one prop would force you to
choose between the correct outline for a screen reader and the correct size for the design.

## The heaviest weight is semibold

The `weight` prop accepts three names: `regular`, `medium` and `semibold`. They map to
`--font-weight-regular`, `--font-weight-medium` and `--font-weight-semibold`.

There is no bold. The system already ranks text two ways, with the nine size steps and with
three text colours, and a bold weight would be a third way that fits neither. In practice, bold
also spreads until everything on a screen is bold. A bold `weight` is a type error, and there is
no bold token. If your app needs a bold face for a specific case, set it with `style`.

Rank with size, and make text quieter with colour:

```tsx
// Not this: a heavier weight at the same size
<Heading size="6" weight="semibold">Notifications</Heading>
<Text size="6" weight="medium">Choose what reaches you</Text>

// This: a smaller step and a quieter colour
<Heading size="6">Notifications</Heading>
<Text size="3" emphasis="medium">Choose what reaches you</Text>
```

## Three font tokens

Components read their font from one of three tokens: `--font-body`, `--font-heading` and
`--font-mono`. By default, the body font is the system interface font, and the heading font
follows the body font. To use your own fonts, set these tokens on `:root` in your stylesheet.

- **Body font:** `Text`, `Blockquote`, `Link`, button labels and field values
- **Heading font:** `Heading`
- **Mono font:** `Code` and `CodeBlock`

`Code` sets its text slightly smaller than the text around it, because a monospaced face is
wider and taller and looks one step larger at the same size.

`Kbd` uses the body font rather than the mono font. A monospaced font squeezes symbols such as ⌘
to fit a fixed width, and every platform shows keyboard shortcuts in its interface font.

## Emphasis sets the text colour

On `Text` and `Heading`, `emphasis` picks one of three text colours:

- **Loud:** `--color-text`, the full-contrast colour
- **Medium:** `--color-text-muted`, for supporting text
- **Quiet:** `--color-text-faint`, for text that nobody needs to read

If you add a `tone`, the same three levels use colours from that family instead.

Text is loud unless you say otherwise, because full contrast is the correct default for reading
and a grey paragraph looks optional. Quiet is below the minimum contrast for body text on
purpose. Use it for something that nobody has to read or act on, such as a disabled option, and
never for a paragraph.

On a button, `emphasis` does a different job: it picks the fill. The word means the same thing
in both places, which is how loud the element is.

## Text adapts to the device

Two things change with the device, and they change for different reasons:

- **Reading sizes grow on a touch screen:** Steps 1 to 4 each move up one step, which takes body
  text from 16 to 18 pixels. You hold a phone or a tablet closer to your face than a monitor,
  and Apple publishes one Dynamic Type table for both iPhone and iPad, so a tablet gets the
  same sizes as a phone.
- **Display sizes shrink on a narrow window:** Steps 8 and 9 each move down one step, which
  takes a page title from 44 to 32 pixels. A 64-pixel title on a 375-pixel screen fits about
  seven characters on a line, and a narrow browser window on a laptop has the same problem.

Each rule moves only its own steps, so the two never conflict on a phone, where both apply. A
tablet in landscape gets the larger reading text and keeps full-size titles, while a narrow
desktop window gets smaller titles and keeps its reading text.

Both rules apply automatically. Because a step can resolve to different sizes on different
devices, don't build a layout on a pixel value you measured from one step.

## The five steps for a screen

These five steps are the house style. They are a judgment rather than a measurement. Spacing
follows the `density` setting, but nothing sets type sizes for you, so the rule is written here:

- **Page title:** size 8
- **Section title:** size 7
- **Card or block title:** size 6
- **Body text:** size 3
- **Labels and small print:** size 2

A card title over body text puts 24 pixels over 16, which reads clearly as a step down. Use
steps 4, 5 and 9 only for cases these five do not cover, such as a hero or a large number.

Rank by size rather than by weight. A 16-pixel title over a 14-pixel body is only 1.14 times the
size, which is too small a difference to read as a hierarchy. Larger steps also have tighter
letter spacing: steps 1 to 3 use none, and the spacing tightens from step 4 up.

Don't use size 1 on a composed screen. Twelve pixels is for text at the edge of a screen, such
as a legal line or the cells of a dense table. When something matters less, use the muted or
faint colour at size 2 or 3. If a screen only fits with 12-pixel text, it has a spacing problem
rather than a type problem.

This example uses the five steps together:

```tsx
<Stack gap="6">
  <Heading size="8" render={<h1 />}>Billing</Heading>

  <Stack gap="5">
    <Heading size="7" render={<h2 />}>Payment method</Heading>

    <Card size="3">
      <Stack gap="3">
        <Heading size="6" render={<h3 />}>Visa ending 4021</Heading>
        <Text size="3" render={<p />}>Renews on 3 September for 24 dollars.</Text>
        <Text size="2" emphasis="medium">Updated 3 August</Text>
      </Stack>
    </Card>
  </Stack>
</Stack>
```

The page title, the section title, the card title, the body and the small print each sit on a
different step, and the outline stays correct because `render` sets the element while `size`
sets the step.
