One ramp of nine steps sets every word this system draws: body copy, headings, control labels,
field values and code. A step is an index, not a font size. It joins three designed values at
one position. The weight ladder stops at semibold, so you rank with size and with ink.

## One ramp for Text and Heading

`Text` and `Heading` are one type system that reaches two family slots. A step joins three
paired tokens at one index: `--font-size-3`, `--line-height-3` and `--letter-spacing-3`. The
three move together. The system has no global line-height ratio, because one ratio is wrong at
both ends of a range that runs from 12px to 56px.

Size means the same thing on both components. `<Text size="6">` and `<Heading size="6">` are
the same step, and only the family slot and the default weight differ. A control label reads
the same ramp, so a `Button` label and a `Text` beside it cannot drift apart.

## Size prices the type, and render names the document

The visual step and the document outline level are two independent axes, and each has its own
prop.

```tsx
// The page title: an h1 in the outline, priced at the top of the house ladder
<Heading size="8" render={<h1 />}>Billing</Heading>

// A card title: an h3 in the outline, priced two steps down
<Heading size="6" render={<h3 />}>Payment method</Heading>
```

`Heading` renders an `<h2>` at size 6 by default, because a page rarely wants a second `<h1>`.
`Text` renders a `<span>` at size 3. Write `render={<p />}` for a paragraph, because the layout
owns the flow.

The system has no `level` prop, and no `as` prop that does both jobs. One prop for both would
force a choice between a correct outline for a screen reader and a correct picture for an eye.

## Three weights, and semibold is the ceiling

The set is `--font-weight-regular`, `--font-weight-medium` and `--font-weight-semibold`. The
`weight` prop takes those names, and it takes no numbers.

The system refuses the bold weight, and the weight itself is not the problem. The system
already has two designed ways to state that one thing outranks another: the nine-step ramp and
the ink ladder. A 700 face is a third way, and it sits on no ramp. It is one step that lands
wherever a call site puts it, which means on everything at once. This is a judgment.

The refusal lives in the type. The `weight` prop does not accept the value, so the code does
not compile, and the system deletes the token as well. A value that stays reachable is a value
every call site can bring back. An app that needs a 700 face uses `style`.

Rank with size, and shade with ink:

```tsx
// Not this: a heavier face at the same step
<Heading size="6" weight="semibold">Notifications</Heading>
<Text size="6" weight="medium">Choose what reaches you.</Text>

// This: a real step down, and the ink stating "supporting"
<Heading size="6">Notifications</Heading>
<Text size="3" emphasis="medium">Choose what reaches you.</Text>
```

## Three family slots

`Theme` sets `--font-heading`, `--font-body` and `--font-mono`. A component reads a slot, never
a font stack. The `Theme` props are the only place anyone writes a stack.

`Heading` takes the heading slot. `Text`, `Blockquote` and `Link` take the body slot. `Code` takes the
mono slot at a small designed discount, because a mono face runs wider with a taller x-height
and reads one step large at the same font size. `Kbd` is the exception: a keycap takes the
**body** slot, because a mono cell draws ⌘ compact to fit its fixed advance, and every platform
sets a shortcut in the interface sans face.

## Emphasis resolves to ink, and text rests loud

Emphasis is one axis with three resolutions. A control resolves it as a fill. A surface
resolves it as dressing. Type resolves it as a foreground role. Loud reads `--color-text`,
medium reads `--color-text-muted`, and quiet reads `--color-text-faint`. A chosen `tone` moves
the same three rungs onto that family's ink trio.

Text rests loud, which inverts the control default on purpose. Full contrast is the correct
resting state for reading, because a screen ranks its actions and not its paragraphs. A
paragraph that arrives at medium by default states that reading is optional.

Quiet sits below the body contrast floor on purpose. It is the rung for an option the reader
cannot take. Do not use it for a full line of text. Nothing stops you.

## Two bands re-price the ramp

The two bands answer two unrelated questions, and the system keeps them apart.

- **`handheld` raises the reading steps.** It keys on `(pointer: coarse)` and raises steps 1
  through 4. Body moves from 16 to 18. The reason is viewing distance: a held screen is close
  to the eye. Apple publishes one Dynamic Type table for iOS and iPadOS, so the reading
  question does not separate a phone from a tablet.
- **`narrow` lowers the display steps.** It keys on `(max-width: 48rem)` and lowers steps 8 and
  9. A page title moves from 56 to 40. The reason is line length: a 56px title on a 375px
  screen fits about seven characters on a line. A squeezed desktop window has the same problem.

Each band emits only the steps it moves, so the two never conflict on a phone, where both
apply. A tablet in landscape raises its reading steps and keeps its 56px display steps. A
squeezed desktop window cuts the display steps and leaves the reading steps alone.

You opt into nothing. `--font-size-N` stays the one spelling, and a component never learns that
a band exists. A size index names a role on the ramp, so do not build a layout on a pixel value
that you once measured for a step.

## The composition ladder

The ladder below is the house style, and the house style is a judgment. Every distance in this
system answers to an axis. Type has no axis, so a written rule is the only thing between the
system and nine opinions on each screen.

**Five steps, and they are the only five.** Page **8**. Section **7**. Card or block title
**6**. Body **3**. Label and meta **2**. A card title over body is 24 against 16, which is a
real step down. Steps 4, 5 and 9 cover cases these five do not, such as a hero or a display
number. Reach for one as a decision, never as a default.

**Size ranks. Weight does not.** A 16px title over 14px body is 1.14 times the body size, which
is a rounding error rather than a hierarchy. The bigger step also earns the tracking.
`--letter-spacing-N` is 0 through steps 1 to 3, and it turns negative from step 4 up. A title
that stays small never receives that negative tracking.

**Do not use size 1 on a composed surface.** 12px is for marginal text: a footer, a legal line,
a dense table's own chrome. It is not for a label or a caption. The muted and faint ink roles
state that a thing matters less, at 14 or 16. A screen that reaches for 12px to make room has a
spacing problem, not a type problem.

Written out, the five steps look like this:

```tsx
<Stack gap="6">
  <Heading size="8" render={<h1 />}>Billing</Heading>

  <Stack gap="5">
    <Heading size="7" render={<h2 />}>Payment method</Heading>

    <Card size="3">
      <Stack gap="3">
        <Heading size="6" render={<h3 />}>Visa ending 4021</Heading>
        <Text size="3" render={<p />}>Renews on 3 September for 24 dollars.</Text>
        <Text size="2" emphasis="medium">Updated 3 August</Text>
      </Stack>
    </Card>
  </Stack>
</Stack>
```

The page title, the section, the card title, the body and the meta line take five different
steps. The outline is correct at the same time, because `render` states the element and `size`
states the step.
