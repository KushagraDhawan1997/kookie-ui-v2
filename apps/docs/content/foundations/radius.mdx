The `radius` setting on your Theme decides how round your whole app is. Each kind of component
works out its own corner from that one setting, so a button can become a pill while the card
around it stays a card. No component accepts a corner prop.

## Set the radius once, on the Theme

```tsx
<Theme radius="medium">
  <App />
</Theme>
```

`radius` accepts `none`, `small`, `medium`, `large` and `full`. The default is `full`, which
makes buttons, fields and menu rows into pills while cards keep the corners of `large`.

Each value is a set of chosen corners rather than one number multiplied up, and `full` shows
why. CSS limits a corner to half the shorter side of its box, so one very large number turns a
button into a pill and also turns a dialog into a lens. No multiplier can round the button
fully and still leave the dialog a rectangle, but a set of chosen values can.

The setting lives on the Theme rather than on each component because roundness only reads as
part of the product when every screen agrees. If one card could be rounder than the next, the
corner would stop telling you anything. This is a judgment.

## Use the token for the kind of component

The theme publishes a separate set of corners for each of five kinds of element:

```css
--radius-control-2   /* a size 2 button, text field or select trigger */
--radius-surface-3   /* a size 3 card */
--radius-overlay-3   /* a size 3 dialog */
--radius-row-2       /* a size 2 menu or select row */
--radius-mark-2      /* a size 2 checkbox */
```

In your own CSS, write the token for the kind of element you are building, such as
`--radius-control-2`, and never a raw step from the palette. Two kinds can have the same value
at one setting and different values at another, and the wrong token gives you the wrong shape
with no error.

The sets are separate because a corner has to be about the same fraction of its box to look the
same. A checkbox is much smaller than a button, and a menu row is shorter than one, so a
button's corner would turn the checkbox into a circle or ask for more curve than the row has
room for.

The sets also respond to different settings. Control corners change with `density`, because a
denser control is smaller and needs a smaller corner. Card and dialog corners change only with
the `size` of the component, because density changes a card's padding rather than its box.

## Corners that fit inside each other

When one rounded shape sits inside another, the two curves look right only if they share a
centre. Otherwise the inner corner cuts into the outer one or leaves a visible gap. The system
works this out for you in three places:

- **Panels with rows:** The corner of a `Menu` or `Select` list equals the corner of its rows
  plus the panel's padding.
- **Nested cards:** A `Card` inside another `Card` or a `Surface` takes the outer corner minus
  the outer padding, so it is always a little squarer than its container.
- **Dialogs:** A `Dialog` takes the corner of a card one size larger, so it is rounder than the
  cards you put inside it.

You never supply an offset. At `none`, there is no curve to fit, so nothing gains a corner from
its padding.

## Shapes that stay round

`none` squares everything, pills included, except a few shapes whose roundness is part of what
they mean:

- **Radio:** A radio stays a circle, because a square radio looks like a checkbox.
- **Slider handle and switch thumb:** These stay circles, because every platform draws them
  round and a square handle does not look draggable.
- **Switch track:** The track stays a capsule, because a round thumb only fits inside a
  curved track.
- **Avatar and Badge:** A face and a count marker are round on every platform, so these stay
  round too.

The rule also works in the other direction. At `full`, a checkbox stops at the corner it has at
`large`, because a round checkbox looks like a radio.

## Change the corner for one region

To give one region a different corner, nest a Theme on an element that your layout already
has:

```tsx
<Theme radius="medium">
  <Stack gap="5">
    <Card size="3">
      <Stack gap="3">
        <Heading size="6">Billing</Heading>
        <TextField size="2" placeholder="Card number" />
        <Button emphasis="loud">Save card</Button>
      </Stack>
    </Card>

    <Theme radius="none" render={<section />}>
      <Card size="3">
        <Text size="3" emphasis="medium">Legacy invoices</Text>
      </Card>
    </Theme>
  </Stack>
</Theme>
```

The first card, its field and its button each take their own `medium` corner. The nested
section squares everything inside it, apart from the shapes listed above.

A nested Theme is one visible line that changes a whole region. A corner prop on each card
would let every screen make its own choice, and your app would soon have many.
