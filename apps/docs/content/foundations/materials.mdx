Material is what your app is made of. It is one setting on the Theme with four values, and no
component picks its own.

A material keeps a foreground readable over whatever passes behind it, so it takes effect only
where something does pass behind a panel.

## One material for the whole app

```tsx
<Theme material="regular">
  <App />
</Theme>
```

The four values are `solid`, `thin`, `regular` and `thick`, and `solid` is what you get by
default. Solid is a material rather than the absence of one, and it is the value where light
stops passing through.

One value covers everything, because every panel in one app is made of the same stuff. A dialog
still feels heavier than a menu, because it covers far more of the screen and dims everything
behind it. Glass over 900 pixels of app hides more than the same glass over a 170-pixel menu.

No component takes a `material` prop. To change it for one part of your app, nest a `<Theme
material>`, the same escape every other setting uses.

## Glass only works where there is something behind it

The Theme sets the value. Where you place things decides where it takes effect.

Glass over a plain background blurs nothing, but it still reads the background on every
repaint. The material therefore reaches only the components you have marked as sitting over
something.

Mark the place, not each control.

```tsx
<Theme material="regular">
  <Box className="editor-canvas">
    <Box backdrop p="2">
      <Flex gap="2" align="center">
        <Button emphasis="quiet">Crop</Button>
        <Button emphasis="quiet">Rotate</Button>
        <Separator orientation="vertical" />
        <TextField size="2" placeholder="Layer name" />
        <Button emphasis="loud">Export</Button>
      </Flex>
    </Box>
  </Box>
</Theme>
```

One `backdrop` marks the toolbar. Every control inside it becomes glass, keeps its own
loudness, and shows the artwork underneath. A toolbar of five controls is one fact, not five
props.

`backdrop` is a boolean. It says where a panel sits, never how thick the glass is.

`Card`, `Button`, `TextField`, `TextArea`, `SelectTrigger`, `SegmentedControl`, `Notice`,
`Badge` and `Composer` each take `backdrop` when you want a single control to be glass.
`backdrop={false}` marks a smaller region as plain again.

The five `Shell` panels take it too: `ShellHeader`, `ShellRail`, `ShellSidebar`,
`ShellInspector` and `ShellBottom`. A sidebar that floats over a canvas is the clearest case
for glass in a whole app. `ShellContent` does not take it, and it is the one place the library
refuses the prop rather than defaulting it, because the work area is the bottom of the stack
and nothing ever passes behind it. To build a vibrant region inside the work area, put a `Box
backdrop` or a `Card backdrop` in it, because a solid panel hosts glass.

The material is resolved in this order: the component's own prop, then the region it is in,
then `solid`. Floating panels mark themselves, because a popup always covers something.

An unmarked control sitting in ordinary page flow stays solid and costs you nothing. A blur
filter on something with nothing behind it re-reads the page on every paint and produces no
visible result, which is the performance reason for the rule.

## Glass does not stack

A panel that paints translucent glass makes everything inside it solid. Those children take the
same transparency and add no blur of their own. You cannot put glass on glass, and the system
stops you, so it is not a rule you have to remember.

The reason is physical. A panel looks like glass because it blurs what is behind it. On top of
another panel there is nothing left to blur, so the child reads the background again, blurs an
already-blurred image, and looks like a sticker.

A solid panel also resets the region, so an unmarked control on an opaque card stays solid.

A solid card can still hold glass. Ask for it inside a card and you get it, because a map or a
feed inside a card does have content passing behind it.

```tsx
<Card>
  <Box backdrop>
    {/* your own map canvas paints here */}
    <Button>Recenter</Button>
  </Box>
</Card>
```

A `<Theme>` resets it too, which keeps menus correct. A menu opened from a glass card is glass
again, because it paints over the page rather than inside the card.

Building your own panel takes one line:

```tsx
const material = useMaterial({ backdrop: true });
return <div className="kui-surface" data-material={material} />;
```

## Glass uses the component's own colour

A material changes a fill; it is not a fill itself. It takes the colour the component would
have painted, mixes it toward transparent, and adds the blur. It never picks a colour of its
own.

Both of your other choices survive. A loud accent button under glass is translucent accent, a
medium button is a soft tint, and a quiet button is blur with no fill at all. Each one keeps
its own label colour, because the fill is still its own fill.

## When to use it

Use glass where content passes behind a panel: a toolbar over a canvas, a panel over a hero
image, chrome that content scrolls underneath. Fixed chrome is the best case, because a blurred
element that moves must re-read its background on every frame.

Do not use it over a solid surface. It blurs nothing, it looks like a smudge, and it costs a
background read per element.

There is no free glass. Every panel that paints it costs a background read. To avoid that cost
in one region, set `material="solid"` on a nested Theme.

Two accessibility settings change the glass without you doing anything. If someone has asked
for reduced transparency, every panel becomes solid and the filter is removed. If someone has
asked for higher contrast, each value becomes more opaque, and the thinnest moves furthest, so
the three values stay clearly different from each other.

The highlight along the top edge stays in both cases. It is a gradient inside the panel, so it
cannot lower anyone's contrast, and it tells you the panel is a physical thing catching light.
