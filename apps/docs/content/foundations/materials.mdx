Material describes what your app is made of. It's a single Theme setting with four values, and
no component picks its own.

A material keeps a foreground readable over the content passing behind it, so it takes effect
only where content actually passes behind a panel.

## One material for the whole app

```tsx
<Theme material="regular">
  <App />
</Theme>
```

The four values are `solid`, `thin`, `regular`, and `thick`, and `solid` is the default, which
lets no light through.

One value covers the whole app, because every panel in an app is made of the same material. A
dialog still feels heavier than a menu, because it covers far more of the screen and dims
everything behind it, so the same glass hides more over 900 pixels of app than over a 170-pixel
menu.

No component accepts a `material` prop. Nest a `<Theme material>` to change the material for one
part of your app, which is how every other Theme setting works as well.

## Glass needs something behind it

The Theme sets the value, while the place you put a component decides where that value takes
effect.

Glass over a plain background blurs nothing and still reads the background on every repaint, so
the material reaches only the components you mark as sitting over content.

Mark the place rather than each control.

```tsx
<Theme material="regular">
  <Box className="editor-canvas">
    <Box backdrop p="2">
      <Flex gap="2" align="center">
        <Button emphasis="quiet">Crop</Button>
        <Button emphasis="quiet">Rotate</Button>
        <Separator orientation="vertical" />
        <TextField size="2" placeholder="Layer name" />
        <Button emphasis="loud">Export</Button>
      </Flex>
    </Box>
  </Box>
</Theme>
```

One `backdrop` marks the toolbar, which turns every control inside it to glass while each
control keeps its own loudness and shows the artwork underneath.

`backdrop` is a boolean that says where a panel sits, and it never says how thick the glass is.

Set `backdrop` on a single control to make that control glass. These components accept the
prop:

- `Card`
- `Button`
- `TextField` and `TextArea`
- `SelectTrigger`
- `SegmentedControl`
- `Notice`
- `Chip`
- `Composer`

Set `backdrop={false}` to return a smaller region to plain.

The five `Shell` panels accept `backdrop` as well: `ShellHeader`, `ShellRail`, `ShellSidebar`,
`ShellInspector`, and `ShellBottom`. A sidebar floating over a canvas is the clearest case for
glass in an app.

`ShellContent` accepts no such prop, because the work area sits at the bottom of the stack and
nothing passes behind it. You can still build a vibrant region inside the work area by placing a
`Box backdrop` or a `Card backdrop` in it, since a solid panel can hold glass.

A panel that becomes a drawer needs no prop either. On a narrow window a nav column opens over
the page with a scrim under it, in the way a dialog does, so the drawer takes the theme's
material automatically. The prop matters only while the panel stands in the frame.

The system resolves the material in this order:

1. A panel that covers something.
2. The component's own prop.
3. The region that the component sits in.
4. `solid`.

A panel that covers the page marks itself, because content always sits behind it.

An unmarked control in the ordinary page flow stays solid and costs you nothing, which is the
performance reason behind the rule: a blur filter with nothing behind it re-reads the page on
every paint and produces no visible result.

## Glass doesn't stack

A panel that paints translucent glass turns everything inside it solid, so its children take the
same transparency and add no blur of their own. Glass never stacks on glass, and the system
enforces that rather than asking you to remember it.

The reason is physical. A panel looks like glass because it blurs the content behind it, and on
top of another panel no content remains to blur, so the child reads the background again and
blurs an image that is already blurred, which arrives as a sticker.

A solid panel also resets the region, which keeps an unmarked control on an opaque card solid.

A solid card can still hold glass, and asking for glass explicitly inside a card gives you glass,
because a map or a feed inside a card does have content passing behind it.

```tsx
<Card>
  <Box backdrop>
    {/* your own map canvas paints here */}
    <Button>Recenter</Button>
  </Box>
</Card>
```

A `<Theme>` resets the region as well, which keeps menus correct: a menu opened from a glass card
is glass again, because it paints over the page rather than inside the card.

One line builds your own panel:

```tsx
const material = useMaterial({ backdrop: true });
return <div className="kui-surface" data-material={material} />;
```

## Glass uses the component's own colour

A material modifies a fill rather than being one. It takes the colour the component would paint,
mixes it towards transparent, and adds the blur, so it never selects a colour of its own.

Your tone and emphasis survive unchanged. Under glass a loud accent button is translucent accent,
a medium button is a soft tint, and a quiet button is blur with no fill, while each keeps its own
label colour because the fill remains its own.

## When to use glass

Use glass where content passes behind a panel, such as:

- a toolbar over a canvas
- a panel over a hero image
- chrome that content scrolls under

Fixed chrome is the best case, because a blurred element that moves must read its background
again on every frame.

Avoid glass over a solid surface, where it blurs nothing, arrives as a smudge, and still costs a
background read.

Every glass panel costs a background read, so set `material="solid"` on a nested Theme to remove
that cost from one region.

Two accessibility settings change the glass automatically:

- **Reduced transparency** turns every panel solid, because the system removes the filter.
- **Higher contrast** makes each value more opaque, and the thinnest value moves furthest, which
  keeps the three values clearly apart.

The highlight along the top edge survives both, because it is a gradient inside the panel and
cannot lower any contrast. It shows that the panel is a physical thing catching light.
