Material is what the application is made of. It is one value on the `Theme`, with four
levels. No component chooses a material.

The material makes a foreground readable over whatever passes behind it. A material therefore
takes effect only where something passes behind a pane.

## One material for the whole app

```tsx
<Theme material="regular">
  <App />
</Theme>
```

The four levels are `solid`, `thin`, `regular` and `thick`. `solid` is the default. `solid` is a
material, not the absence of one. It is the level that stops all light.

One value covers the whole application. Every pane in the application uses the same material,
at the same thickness. A dialog still reads heavier than a menu, for a different reason: it
covers more of the screen and it carries a scrim. The same glass over 900 pixels of application
hides more than the same glass over a 170-pixel menu.

No component takes a `material` prop. To change the material for one part of the tree, nest a
`<Theme material>`. Every other axis uses the same escape.

## Glass takes effect where a backdrop exists

The theme sets one value. Placement decides where that value takes effect.

Glass over a plain background blurs nothing. It still reads the backdrop on every paint. So the
theme's material reaches only the components that sit over something.

Mark the place. Do not mark each control.

```tsx
<Theme material="regular">
  <Box className="editor-canvas">
    <Box backdrop p="2">
      <Flex gap="2" align="center">
        <Button emphasis="quiet">Crop</Button>
        <Button emphasis="quiet">Rotate</Button>
        <Separator orientation="vertical" />
        <TextField size="2" placeholder="Layer name" />
        <Button emphasis="loud">Export</Button>
      </Flex>
    </Box>
  </Box>
</Theme>
```

One `backdrop` marks the toolbar. Every control inside it resolves `regular`, keeps its own
loudness, and reads the artwork under the pane. A toolbar of five controls is one fact, not five
props.

`backdrop` is a boolean. It says where the pane sits. It never says how thick the glass is.

`Card`, `Button`, `TextField`, `TextArea`, `SelectTrigger` and `SegmentedControl` each take
`backdrop` for a single control. `backdrop={false}` marks a sub-region as plain again.

The system resolves the material in this order: the component's own prop, then the region, then
`solid`. A floating pane passes `backdrop` itself, because a popup always covers the application.

An unmarked control in normal flow resolves `solid` and costs nothing. This is the performance
reason for the rule. A backdrop filter on a control with no backdrop reads the page on every
paint and produces no visible result.

## Glass does not stack

A pane that paints a translucent layer sets the material for everything inside it. Those
children take the same transparency and add no blur of their own. You cannot put glass on
glass. The system prevents it, so you do not have to remember the rule.

The reason is physical. A pane reads as glass because it blurs what is behind it. On top of a
second pane, nothing remains to blur. The child then reads the backdrop again, blurs an image
that is already blurred, and reads as a sticker.

A solid pane also resets the region, so an unmarked control on an opaque card stays solid.

A solid surface can still hold glass. An explicit statement inside a card wins, because a map or
a feed inside a card does have content passing behind it.

```tsx
<Card>
  <Box backdrop>
    {/* the consumer's own map canvas paints here */}
    <Button>Recenter</Button>
  </Box>
</Card>
```

A `<Theme>` also resets the pane scope. This keeps portals correct. A menu opened from a glass
card is glass again, because it paints over the page and not inside the card.

Your own pane takes one line:

```tsx
const material = useMaterial({ backdrop: true });
return <div className="kui-surface" data-material={material} />;
```

## Glass uses the component's own fill

A material changes a fill. It is not a fill. It takes the fill the component would have
painted, mixes it toward transparent, and adds the blur. It never picks a colour of its own.

Both axes therefore survive the glass. A loud accent button under glass is translucent accent. A
medium button is a soft tint. A quiet button is blur with no fill. Each loudness level keeps
its own label colour, because the fill is still that level's fill.

## When to use glass

Use glass where content passes behind a pane. A toolbar over a canvas, a panel over a hero image,
and chrome that content scrolls under are the correct cases. Fixed chrome is the best case,
because a blurred element that moves reads its backdrop again on every frame.

Do not use glass over a solid surface. It blurs nothing, it reads as a smudge, and it costs one
backdrop read for each element.

There is no free glass. Glass costs a backdrop read for each pane that paints one. To avoid the
cost in a region, set `material="solid"` on a nested `Theme`.

Two settings change the glass without a prop. `prefers-reduced-transparency` seals every pane
and removes the filter. `contrast="high"` makes each level more opaque, so the thinnest level
moves furthest and the three levels stay separate. The rim stays, because it is a gradient
inside the pane. It cannot lower anyone's contrast, and it shows that the pane is a physical
object.
