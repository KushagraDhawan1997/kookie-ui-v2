`depth` is a Theme setting with two values. It answers one question: does this app have light
in it? No component takes a shadow prop, and no screen picks a shadow. Each kind of component
decides one time whether it casts a shadow.

## Set depth once, at the root

```tsx
<Theme depth="elevated">
  <App />
</Theme>
```

`elevated` is the default. It means that the app has a light source. Cards sit above the page,
the main action catches light, and handles lift.

`flat` means that the app has no light source. Lines and fills do all the separation.

Depth is a Theme setting because people see light as a property of the room, not of one object.
Two cards on one screen, one raised and one flat, show two different rooms. So there's no
`shadow` prop, `elevation` prop or `raised` boolean.

## What casts a shadow

These components cast a shadow:

- `Card`, and the panels that look like a card
- a **loud** button
- the handles on sliders and switches
- `Kbd`

These components don't cast a shadow:

- `Surface`
- text fields and text areas
- medium and quiet buttons
- checkboxes
- progress bars
- separators
- tab bars

Only two kinds of thing get a shadow: the thing that you act on, and the thing that floats
above everything else. Three of the refusals change the code that you write.

- **A ground casts nothing.** A `Surface` is what objects sit on. It isn't an object itself. To
  lift something, put a `Card` inside the Surface. The ground under the card stays in place.
- **A field is recessed, not raised.** To lift a form, put the form in a Card. The fields stay
  recessed inside the card.
- **A medium button is flat.** Use `emphasis` to rank two buttons. Don't use depth. The loud
  button casts a shadow and catches light. The medium button does neither. This difference
  shows the rank.

A checked checkbox catches light, but it never casts a shadow. Checking it fills a recess. It
doesn't lift anything.

**A disabled card loses its shadow.** A shadow shows that a thing sits above the page and that
you can pick it up. You can't pick up a disabled card, so it goes back down to the page.

## Turn off the light for one region

Nest a Theme to remove the light from one region of an elevated app.

```tsx
<Theme depth="elevated">
  <Stack gap="5">
    <Card size="3">
      <Stack gap="3">
        <Heading size="6">Production</Heading>
        <Text size="3" emphasis="medium">Deployed 4 minutes ago.</Text>
        <Button emphasis="loud">Promote build</Button>
      </Stack>
    </Card>

    <Theme depth="flat" render={<section />}>
      <Card size="3">
        <Text size="3" emphasis="medium">Archived environments</Text>
      </Card>
    </Theme>
  </Stack>
</Theme>
```

The first card lifts, and its loud button catches light. The second card shows its edge with a
thin line. Nothing inside the nested Theme casts a shadow. This includes a menu that opens from
the nested Theme.

## Bigger boxes get longer shadows

There are five shadow values. The first value is a recess, and the other four are drops.

Each drop has the same structure at a different height. A tight contact line under the edge
keeps the shadow sharp. Softer layers move inward, so the depth falls *under* the element. It
doesn't spread out to the sides.

**A smaller thing casts a smaller shadow.** If it doesn't, it looks swollen. A card is a bigger
box than a menu, so a card uses a value with a longer reach than a floating panel. This
relationship is an observation. The exact values are a judgment.

`--shadow-1` to `--shadow-5` are public. They're a resource, not a setting. Components never
name them directly. They go through the theme. If you build something that the package doesn't
ship, use `style`:

```tsx
<Box style={{ boxShadow: "var(--shadow-3)" }}>Custom pane</Box>
```

`Box` has no `shadow` prop, because Box is layout and a shadow is paint.

## A popup has to show where it ends

A popup covers the content under it, so you must be able to see its edge.

In an elevated app, the shadow shows the edge. In a flat app, nothing casts a shadow, including
menus and dialogs. So a popup draws a thin line.

A `Dialog` casts no shadow of its own in either app, because **the dimmed background is the
separation**. The whole window goes dark. This shows what the dialog covers more completely than
a shadow can. The panel keeps the ordinary card shadow for the current depth setting.

## Handles cast a shadow even in a flat app

These cast a shadow in every app, flat apps included:

- the slider handle
- the switch thumb
- the selected segment of a segmented control
- `Kbd`

The four shapes that keep their shape at `radius="none"` follow the same idea: the appearance
carries the meaning. A handle that doesn't sit above its track stops looking like a handle. A
handle's position *is* the value that it sets, so the control stops working. Every platform
ships handles with a shadow in every context.

`Kbd` is the opposite case. A key presses *into* its surface, so its depth is a recess and not a
lift.

A disabled handle loses its shadow and dims, but it keeps its colour. A grey handle in a grey
track is hard to see.
