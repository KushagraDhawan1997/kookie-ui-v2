You tell a component what a colour means, and the theme works out the value. That value
changes with light and dark mode, with the contrast setting, and with the surface underneath,
so you never write a hex value and never have to remember a palette.

## Name the meaning, and let the theme choose the colour

```tsx
// Do not do this.
<Text style={{ color: "#E5484D" }}>Payment failed</Text>

// Do this.
<Text tone="destructive">Payment failed</Text>
```

A hex value is fixed, so it stays the same in dark mode, ignores the high-contrast setting and
survives a change of brand colour. `tone="destructive"` avoids all three problems, because the
theme produces the value for the current mode and setting.

There's no `color` or `variant` prop. If you really must set a colour yourself, use `style`,
where it stays easy to spot in a review. Needing `style` for colour often means that a colour
family is missing, and that family belongs in the theme configuration instead.

## The ten colour families

The theme generates each family from a short recipe, usually a hue and a saturation. Every
family shares one lightness scale of twelve steps, so step 9 of red and step 9 of blue have the
same lightness.

| tone | what it is for |
|---|---|
| `neutral` | Text, hairlines, backgrounds and anything that has no meaning of its own. This is most of an interface. |
| `accent` | Your brand, used at full strength once on each screen. In the default theme the accent is grey, so a loud accent button is near-black in light mode and near-white in dark mode. |
| `blue` `green` `orange` `amber` | Colour as data: a chart series, a project label or a category, where the colour itself is the information. |
| `destructive` | An action that removes something, and the error state. |
| `success` `warning` `info` | Status: something worked, something needs attention, or the text adds context. |

Use a meaning name when the item carries a meaning, such as an error. Use a category name when
it only marks a category, such as one series in a chart.

### Meanings and categories are separate families

`success` and `green` look the same today, but they are two separate families, so you can
change one without the other. If you move `success` towards teal, the green in your charts
stays where it is. `warning` and `amber`, and `info` and `blue`, work the same way.

Don't write `tone="green"` when you mean success. The screen looks right today, and it becomes
wrong the first time either family changes.

## Components use named roles

The twelve-step scale is public, but components don't use step numbers. They use named roles,
which is why every value moves together when you change a family.

```css
--accent-soft / -soft-hover / -soft-active      /* tinted fills */
--accent-solid / -solid-hover / -solid-active   /* strong fills */
--accent-border
--accent-text                                   /* links and text on a tint */
--accent-contrast                               /* readable text on a strong fill */
--accent-ink / -ink-muted / -ink-faint          /* the three text colours */
--accent-glyph                                  /* icons and small marks */
--accent-a1 … --accent-a12                      /* semi-transparent steps */
```

Every family has the same roles, so `--destructive-solid`, `--success-ink` and
`--warning-border` all exist.

## Tinted fills and borders are grey

A tinted fill is almost transparent, so you see mostly the page through it and its colour tells
you very little. For that reason, when you give a component a tone, its tinted fills and its
borders are grey in every family. A medium button, a quiet button under the pointer and a chip
all have a grey fill, and the family shows in the text instead. Strong fills keep their colour,
so a loud destructive button is red.

The accent goes one step further, which only matters once your accent has a hue. Its two
quieter text colours and the faint tint on a panel such as a `Notice` are grey too. The other
families carry meanings, and a pale red still reads as danger. The accent carries your brand,
and a faint wash of a brand colour no longer looks like that brand.

## Icons have their own colour

Icons use `--{tone}-glyph`. It keeps the family's full saturation at a lightness that stays
legible for a small mark in each mode.

The other roles don't work for icons. A strong fill has no single value that is legible on both
white and black. A text colour is legible everywhere, but it loses saturation to reach its
reading contrast, so a blue icon in the text colour looks like a dull navy.

## The three text colours

On text, `emphasis` picks one of three colours:

- **Loud:** `--color-text`, the default.
- **Medium:** `--color-text-muted`.
- **Quiet:** `--color-text-faint`.

When you add a `tone`, the same three levels come from that family instead.

```tsx
<Card size="3">
  <Stack gap="3">
    <Flex gap="2" align="center" justify="space-between">
      <Heading size="6">Invoice 4021</Heading>
      <Text size="2" tone="destructive" weight="medium">Payment failed</Text>
    </Flex>
    <Text size="3">Your card was declined on 3 August.</Text>
    <Text size="3" emphasis="medium">We will try again on 10 August.</Text>
    <Flex gap="3">
      <Button emphasis="loud">Update card</Button>
      <Button emphasis="quiet" bordered>Contact support</Button>
    </Flex>
  </Stack>
</Card>
```

The heading and the first line are loud. The retry date is real information that the screen
does not need to stress, so it is medium.

The theme calculates the medium and quiet colours against a contrast target, separately for each
family and each mode, so every family reaches the same contrast at the same level:

- **Loud:** the family's own text colour, with no target. It is the colour you read most, and it
  is already well above every minimum.
- **Medium:** exactly the APCA minimum for reading text, Lc 60, which is a measured limit. Use it
  for a placeholder, a timestamp or a group label.
- **Quiet:** Lc 30, below the reading minimum on purpose. Use it for something that is switched
  off, such as a menu option that you can't choose.

Never set a paragraph in quiet. If some text matters less, keep it loud at a smaller size, or
make it medium.

## High contrast

`contrast="high"` is a Theme setting, not a prop on each component. The theme also follows the
operating system, so a person who asks their system for more contrast gets it without any work
from you.

```tsx
<Theme contrast="high">{children}</Theme>
```

At the normal setting, the colour of a resting border or fill is a judgment of taste and has no
minimum contrast. Under `contrast="high"`, borders and fills must meet measured minimums. Text,
the focus ring and the error border meet their minimums at every setting and in both modes,
because all three carry information.

The high setting raises each colour as far as that colour can go, instead of adding a fixed
amount everywhere. A bright hue such as yellow turns olive if you darken its border, so it
gets its extra contrast in the text instead. Some colours therefore don't change at all, and
that is intentional.

## The three background colours

Three named backgrounds sit under everything else. From the bottom up:

```css
--color-page      /* your app's background */
--color-ground    /* a region that holds objects, such as a sidebar */
--color-surface   /* the opaque fill of an object, such as a card */
```

<ColorGrounds />

The library doesn't paint the page background, because every nested `Theme` would paint over
it again. Paint it yourself with `--color-page`. No component uses that role.

`--color-ground` is the region under objects, and a `Surface` uses it. `--color-surface` is the
object itself, such as a `Card`, and it stays opaque unless the theme's material makes it glass.

Light and dark mode arrange these colours differently, which changes how you build a screen:

- **Light mode:** the page and a card are the same white, so a card on the page is set apart
  only by its shadow, or by its hairline in a flat theme. A ground is slightly darker than both.
  This is why `depth` matters more in light mode.
- **Dark mode:** all three are different. The page is darkest, a ground is slightly lighter,
  and a card is lightest, with small steps between them.
