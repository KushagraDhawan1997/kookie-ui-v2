The `size` prop picks a step on a scale rather than a measurement. `size="2"` asks for the second
step, and the theme decides what that step is worth for the current density and input device.

The same number can mean different things on different components, because each component
measures something different. On a `Button`, size sets the height of the control. On `Text`, it
sets how large the words are.

## Sizes are steps

A size 2 `Button` is 32 pixels tall at default density with a mouse, and 44 pixels tall on a
touch screen. You don't write either number, so your code stays the same when the numbers change.

The steps come from fixed lists. Controls accept `"1"` to `"4"`, and `Text` and `Heading` accept
`"1"` to `"9"`. There's no `size="2.5"` and no way to pass a length. If one screen could invent a
value between two steps, sizes would stop matching across your app.

Components use one of three scales:

- **Height:** `Button`, `TextField`, `Select` and the other controls that hold a label or a value.
- **Padding and corner:** `Card` and `Surface`.
- **Mark:** `Checkbox`, `Radio`, `Switch` and the handle of a `Slider`.

So `size="3"` on a `Card` and `size="3"` on a `Button` are not the same size, because each is the
third step of a different scale. Choose the size that looks right for each component rather than
matching the numbers.

## One size sets the whole control

When you set `size` on a control, it gets a group of values that were chosen to work together:

- its height
- its side padding
- its corner
- its icon size
- the gap between the icon and the label
- the size of the label text.

The system doesn't calculate these from one base number. Every combination of density and input
device has its own values, written out in full:

```css
/* Default density, mouse */
--control-height-2: calc(32px * var(--scale));
--control-px-2: calc(10px * var(--scale));
--icon-size-2: calc(16px * var(--scale));

/* Default density, touch screen */
--control-height-2: calc(44px * var(--scale));
--control-px-2: calc(13px * var(--scale));
--icon-size-2: calc(20px * var(--scale));
```

Because each value is written out, correcting one of them leaves the rest where they are. A
single multiplier would move them all together.

The height is a minimum rather than a fixed value. When a person enlarges their text to 200%, or
a label wraps onto a second line, the control grows instead of cutting off its text. WCAG 2.2
Success Criterion 1.4.4 requires this, so it's a measured limit.

## Checkboxes, radios and switches

A checkbox, a radio, a switch and a slider handle sit next to their label instead of holding
one. Because they contain no text, they don't use the control heights. They use a separate mark
scale. A switch's track is one step larger than a checkbox of the same size, so the switch's
round handle is close to the size of the checkbox beside it.

A checkbox is exactly as tall as one line of the text beside it. This lines it up with its label
without any adjustment, and it grows on a phone because the text grows there too.

### Space stacked checkboxes 12 pixels apart

A checkbox is small, so its tappable area extends past the box you see, to the height of a
`Button` of the same size, up to 44 pixels.

Leave at least 12 pixels between stacked checkboxes. If they sit closer, the lower checkbox's
tappable area covers part of the upper one, and a tap on one checkbox changes the other.

`gap="4"` gives 12 pixels at default density, but only 8 pixels at compact density. Use
`gap="5"`, which is at least 12 pixels at every density.

```tsx
<Stack gap="5">
  <Flex render={<label />} align="center" gap="3">
    <Checkbox size="2" />
    <Text size="3">Notify me when it ships</Text>
  </Flex>
  <Flex render={<label />} align="center" gap="3">
    <Checkbox size="2" />
    <Text size="3">Send the weekly digest</Text>
  </Flex>
</Stack>
```

## Sizes on touch screens

The `pointer` setting on a `Theme` has two main values: `fine` for a mouse or trackpad, and
`coarse` for a finger. Each one has its own complete set of measurements, in the same way that
light and dark mode have their own sets of colours. Your components and size props stay the same,
and only the values change.

The setting follows the input device, not the width of the window. A narrow browser window on a
laptop still uses the `fine` values.

On a touch screen, these values change:

- control heights
- side padding
- icon size
- the gap between an icon and its label
- control corners
- the size of checkboxes, radios and switches
- the size of body text.

The spacing between components stays the same, because a phone has less room than a desktop,
not more.

### Minimum and default tap sizes

WCAG 2.2 Success Criterion 2.5.8 (Level AA) sets a minimum tappable area of 24 by 24 pixels, and
no control in the system is smaller. The smallest control is size 1 at compact density with a
mouse, and it's exactly 24 pixels tall.

On a touch screen, a size 2 control at default density is 44 pixels tall. That matches Success
Criterion 2.5.5 (Level AAA) and Apple's guidance, both based on a fingertip being about 10
millimetres across. A touch control is only smaller than 44 pixels if you choose size 1 or
compact density.

`pointer` accepts `fine`, `coarse` or `auto`. The default is `auto`, which follows the device.
Set `coarse` to see your phone layout on a laptop, including the larger text.

```tsx
<Theme pointer="coarse">
  <Button size="2">Continue</Button>
</Theme>
```

## Buttons inside a field

When you put a `Button` inside a `TextField`, leave its `size` off. The field sets the button's
height from its own, so the button sits inside the field with an even gap around it.

You couldn't choose that size yourself, because no control size fits neatly inside another. The
button's tappable area also matches the field instead of growing to 44 pixels, so the button
never becomes a larger target than the field it sits in.

```tsx
<TextField
  size="3"
  type="password"
  placeholder="Password"
  trailing={<Button emphasis="quiet">Show</Button>}
/>
```

## Components with no size

Some components have no `size` prop, because none of the three scales fits them.

`Progress` is one of them. A progress bar has no handle and holds no text, so it has one
thickness and stretches to the width of its container, like a `Separator`. To make it shorter,
put it in a narrower container.

`Code` has a `size` prop, but it's optional. When you leave it off, the code takes the size of
the text around it, which is what you want for a word inside a sentence.

```tsx
<Box width="240px">
  <Progress value={62} aria-label="Uploading" />
</Box>

<Text size="2">
  Run <Code>pnpm build</Code> before publishing.
</Text>
```
